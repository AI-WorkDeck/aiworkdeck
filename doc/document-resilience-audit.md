# 长文档、识别与补全健壮度审计

日期：2026-09-15。基线：`origin/master` commit `da9330b2ebf6b735ec5e847ea3fc12bb903a3688`（本轮切换至最新主干后重新核查）；实现与测试均在 `sidebar-current` 工作树。依据为当前代码与本地合成测试，未使用客户文档、未调用付费模型或外部工商/法规服务。

## 结论

三万字与三百页是不同的负载维度：字符数影响模型上下文，段落/表格/图片数量影响编辑器与保存。系统已有分页读取、全文批量格式、修订、检查点和保存闸。本轮修复了长文档补全漏尾、条款数量静默截断、部分审校失败隐藏、深入审校总预算及工具错误丢失问题。真实 LOWA 渲染/批量编辑压力测试由总报告记录，不能用这里的模拟测试替代。

## 功能路径与当前边界

| 用户功能 | 实际路径 | 边界与降级 |
| --- | --- | --- |
| 自动补全 | `writingAssistanceHost` 分页读取当前正文 → 本地 `completionLexicon` → `zetaOfficeCompletion` 匹配候选，Tab 接受 | 不调用 LLM。扫描由原先 1,000 段提高到 10,000 段，仍限 200,000 字；文档候选 500，导入项目学习 200 项、每批 50。持续输入学习只处理最近 4,000 字并防抖 8 秒；读到不同修订版本放弃混合结果。 |
| 补全相关资料查询 | 选中文字右键 → `completion/lookup` → 指定来源检索 | 明示用户动作才查询。选中文字最多 160 字；客体与 HTTP 等待 90 秒；一般词库 RPC 15 秒。关闭/换文档后不接受迟到结果。 |
| 即时识别/审校 | `inlineReviewHost` 读取实时正文 → `DocInsightService.review(deep=false)` 本地规则 | 默认不调用模型。最多 10,000 段/200,000 字/60 页读取，单段超 15,000 UTF-16 单位跳过并标截断。只覆盖正文，表格/页眉页脚不在此范围；界面已有明确范围与截断提醒。30 秒 HTTP 等待。 |
| 深入审校（AI） | 显式按钮 → `review(deep=true)` → 10,000 字块、500 字重叠 → 辅助模型 | 前端 HTTP 120 秒。本轮新增模型阶段总预算 105 秒；每块使用剩余预算配置实际 HTTP call timeout，禁自动重试；到界停止后续块，返回已完成发现、`deepComplete=false`，界面已有「未完整完成」提示。 |
| 解析/依据与外部核验 | `insight/parse` 异步管线 → 抽取实体 → 项目文档/外部库 → 一致性校验 | 200,000 字上限，10,000/500 分块；去重后最多 200 实体，每实体最多 20 出处，法条校验最多 30 项，同项目结果缓存 7 天。原文超限显示前缀范围；本轮新增失败块数量与可能遗漏提醒，保留成功块/确定性规则结果。 |
| 条款结构识别 | `doc_get_clauses` → worker 按编号识别 | 最多返回 300 个目录项。本轮补全 `totalClauseCount`、`truncated` 与正确的 `nextStartParagraph`；AI 按续读段号读取剩余正文，不能把返回的 300 项当全文条款数。 |
| AI 读取正文 | `doc_get_document_text` → 带修订号的段落索引缓存 | 默认 200 段，最多 500 段，约 15,000 字预算并返回续读段号。预算在完整段落边界检查，单个异常长段落仍可超过字符预算；即时审校另有单段护栏。 |
| 全文批量格式/替换 | `apply_house_style` / `apply_style_profile` / `find_replace` | 120 秒；格式每 500 顶层元素、批量替换每 30 处协作式让出执行并检查取消。取消保留已经完成的改动并返回数量；不是事务回滚。 |
| 长段插入/续写 | `insert_at_cursor` / `insert_under_heading` / `replace_selection` / `modify_paragraph` / `stream_insert` / `stream_flush` | 最新主干已有 120 秒预算，长插入按本轮/文档/文本指纹去重；显式执行失败解除登记，超时保持登记。既有检查点与修订用于恢复。 |
| 打开/导出/合并 | `load_document` / `export_document` / `build_merge_draft` | 180 秒；本轮补上后端缺失的 `build_merge_draft` 预算，前后端三表一致。文档字节下载另有 60 秒等待；加载/重载失败时禁止空文档覆盖后端。 |

## 本轮修复与证据

1. **自动补全超过 1,000 段漏尾**：原逻辑即使仅三万字，只要短段超过 1,000 就停止。改为与正文审校一致的 10,000 段边界；3,000 短段合成文档的末尾公司现在进入候选与项目学习。未增加任何 LLM 调用。
2. **超过 300 条目录误报完整**：原 `clauseCount` 仅等于返回数组长度。本轮保留该兼容字段，另加全文数量与截断信息；350 条合同合成用例中续读段号 601，准确指向第 301 条（首部 1 段，每条 2 段）。
3. **解析单块坏输出/超时仍显示无保留的完成**：区分有效空结果与无效输出，累计失败块；最终摘要明确提醒实体与一致性结论可能遗漏。三万字四块用例证明第二块失败后仍到达末块、成功块独立记账。
4. **深入审校单块错误丢失先前发现、超时仍继续后续收费调用**：改为保留完成块，遇到传输/账户错误立即停止后续调用（有效响应但 JSON 无效可继续），单调时钟控制 105 秒总预算，按剩余预算创建独立 HTTP 客户端并 `maxRetries(0)`。沿用平台/BYOK/本地路由与原有凭据解析，平台密钥不改变目的地址。客户端超时不代表远端推理或计费已被取消。
5. **工具失败结果不是有效 JSON/丢失原因**：bridge 用 JSON 序列化处理引号、换行与空错误；两层 relay 同时返回 `message` 和宿主实际读取的 `error`。超时带 `EDITOR_RESULT_TIMEOUT`、`outcomeUnknown=true`、`retryable=false`，明确要求先查文档/修订再决定下一步。

6. **多人并发解析无界积压**：异步解析池从无界队列改为 2 工作线程 + 32 排队项；不使用 caller-runs，超载不会在 HTTP 线程里启动收费任务。拒绝会将已登记 RUNNING 改为 FAILED、填写结束时间并释放单飞占位，返回可读繁忙提示。新增 latch 饱和测试覆盖 34 已接纳任务、两次同文件拒绝、队列释放后重新接受，以及仅 35 次成功模型调用。

## 验证

- 前端 completion、inline-review、zeta-relay 套件：115 条通过（包含 3,000 段末尾测试，host 套件 20 条）。覆盖版本变化、旧会话隔离、输入/加载竞争、预算、取消映射、迟到结果和目录续读。
- 新增后端合成 DOCX 测试：300 个分页段、超过 30,000 字，验证 Tika 抽取头部、第 299 页和末尾标记。仅验证文本抽取，不代表 LOWA 排版或性能。
- 新增/更新后端回归：解析失败块与全文 cap；深入审校部分失败保留、单调时钟总预算（105 秒 → 45 秒 → 不再发下一块）；bridge 错误 JSON；真实本地 HTTP 503 只发一次，以及 200ms 慢 HTTP 超时。Maven 最终执行结果由总测试记录归档。
- `node --check office_thread.js` 与三处 action-budget parity 通过。

## 尚需区分的限制

- 超时提示和本地 HTTP 中断不能承诺上游已经停止计算或不计费；本轮保证客户端不自动重试、预算耗尽不再发后续块。
- 105 秒以内未完成的深入审校没有跨次持久化续查游标。已完成结果会返回；下一次整文档重跑仍可能重复花费。需继续大范围核验时，可由 AI 助手按章节读取与核查；持久化后台审校是下一阶段的结构性能力。
- 自动补全文档索引仍是有限候选，并非全文语义搜索。超过 200,000 字或超过候选限额仍不能保证每个名称都有补全候选。
- `insight/parse` 保留 2 个工作线程，本轮将队列限制为 32 项；超载明确提示繁忙、失败落库并清除单飞占位，排队中显示「等待解析」。没有整轮硬截止或用户取消。30 分钟过期回收用于进程重启遗留 RUNNING，不是杀死活跃模型请求。仍缺整轮取消；本地队列饱和测试不代表多人真实上游容量测试。
- 现有正文读取完整段落预算、正则条款结构与不同格式的识别能力有固有限制；表格、扫描件 OCR、复杂修订、图片密集文档需要独立工况。真实 LOWA 150/300 页性能、内存和保存回归以总报告的实际输出为准。

## 节省 token 的建议流程

先做无模型的目录/规则检查与本地候选；只对需要确认的章节执行模型深审。模型以 10,000 字分块，保持重叠与跨块实体合并；对未知写入结果先读回，不自动重写。外部检索按去重实体与缓存执行；局部失败显示范围，不自动把全篇再发一次。格式任务优先使用一次批量格式原语，避免每段一个模型工具调用。
