# 外部依赖整改落实记录（2026-10-21）

对应[排查报告](external-dependency-audit-2026-10-21.md)与 dev-board #1385–#1390。排查报告保留原审计基线，本文记录其后整改。原则是让用户完成原任务：已有适用授权自动继续，需要选择时就地给出可执行选项，安装/恢复后继续原操作；不把损坏、缺字或部分结果标成成功。

## 已落实的产品行为

| 范围 | 改后的行为 | 仍需注意 |
|---|---|---|
| 右键 Office → PDF | 删除有损 Java 重排备用路径；本机 LibreOffice 检测覆盖配置、PATH、Mac 用户 Applications、Windows 常见安装目录。失败区分缺失、不可执行、超时、无输出、坏 PDF；单文件可选择内置引擎继续，自动打开目标、等就绪并导出 | 内置恢复走原有“另存为”，由用户选位置；已有未保存文档按当前内容导出，不替用户保存原件。多文件不假装已合卷 |
| PDF 中文编辑 | 桌面后端使用应用内置中文字体；嵌入与实际字符覆盖验证失败会说明原因，不过滤字符后报成功 | 不能保证所有罕见字/所有字体均可嵌入 |
| 组件与模型 | 空壳完成标记、缺文件与大小变化不再算已安装；完整旧安装可本地迁移记录，无需强制重下。提供修复；下载有无进展/整体上限，取消后等待写入进程退出。服务检测验证对应 HTTP 响应，界面区分基础启动与业务验证 | 不在每次启动重算数 GB 哈希；服务启动不等于真实 OCR/转写/朗读成功 |
| 扫描 PDF → Word | 本地链按 pptx-runtime → MinerU runtime → 模型准备；本地失败可按已保存同意自动云 OCR，也可在原对话选择本地下载或云端，选择后恢复原请求 | OCR 是内容级转换，不保留原布局。每页上传前重验权限/授权/取消；非空页识别失败不输出部分 Word，已识别页可能计费 |
| 本地 OCR 数据去向 | 使用新的显式 local-only 入口，不因配置 token 偷换云端；旧运行包没有入口会明确提供更新/云端选择 | 需要后续发布新版 pptx-runtime；旧包不回退到可能上传的旧接口 |
| Docker / Python 沙箱 | 设置中提供安装/启动说明与重新检测；短期缓存会刷新，同一后端可恢复工具发现 | 不自动绕过系统权限安装 Docker；仍须 daemon、镜像及业务包可用；不降级到宿主 Python |
| 腾讯会议 | 旧后端与现用插件均检查真实 Node / npm package.bin 路径，Windows 不经 cmd 拼接参数；缺 Node、未登录、超时分别说明 | 设置页检测基础 CLI；插件连接、账号授权以插件自身检查为准 |
| 时间轴溯源 Word | 用 Python 标准库生成索引 DOCX，去掉额外系统 Node / npm docx 依赖；包括多页表头、分页与来源链接 | 需要后续资源包更新，现有已下载旧包不会因源码合并改变 |
| DPIA 工作台 | 不依赖 Node RPC 的环境检查入口；报告窗口内也能打开准备指引，保留原项目/填写内容；检查 Node、独立 Python 与锁定依赖、LibreOffice、字体，返回窗口自动重查 | 第三方软件仍需按官网安装/配置路径；检测通过不等于整份评估报告验收通过 |

## 下载、安装与错误处理

应用托管资源包仍沿用签名、归档/文件校验、临时目录与原子切换机制。打开安装网站只称“打开指引”，不会显示安装完成。LibreOffice、Docker、Node 和 DPIA 的系统依赖提供 Mac/Windows 官方入口与步骤；权限或设备管理策略阻止安装时，说明需按安装器错误处理，保留当前工作。

扫描件云 OCR 另有用户级选择和版本化说明，明确数据发往阿里云 OCR 与计费。已有适用同意会被复用；AI 的工具参数不能代替用户授权。其他用途的跨境 AI 同意或 provider 配置不被当成扫描件 OCR 同意。纯白页跳过付费识别；非白页无结果会报出失败页，不静默删除。OCR 原文标点在转 Word 时保留，不被当作 Markdown 语法吃掉。

## 验证证据与边界

- 主任务复核所有集成 diff，并自行运行必要回归；原生子代理做独立调查、局部实现和交叉复核。Kimi 两次未产出合格修改后接回；GLM 完成时间轴与旧 tmeet 初稿，主任务修正 OOXML 结构、JSON 解析和 Windows 路径问题后才纳入。
- Mac 本机 LibreOffice 对合成中文文档验证页眉脚、表格与分页；时间轴合成 100 行导出为 10 页，核对页码、重复表头、全部来源文字并查看实际页图。单纯文本可抽取不等于中文实际显示正确。
- 真实工作台浏览器验证缺依赖后的按钮、打开目标文档、等待引擎、取消、就地恢复与下载回执；PDF 引擎字节、桌面下载回执和部分 API 为合成适配，不声称验证了真实 LOWA 排版或系统“另存为”。
- OCR 用真实聊天组件和 SSE 事件配合合成 API 验证选择/恢复、设置及取消；没有上传用户材料、调用付费 OCR 或用真实客户文档测试。
- 模型检查使用合成缓存及真实下载 SDK 的受控元数据验证。另核验实际已发布 MinerU Mac 包的签名、归档哈希、包内版本与所需模型结构；没有下载数 GB 模型或完成真实 OCR/ASR/TTS 推理。
- DPIA 在本机实际 Node、独立 Python、LibreOffice、内置字体上通过准备检测；没有更改用户系统环境，也不把这些检测称为完整评估业务验收。
- Windows 路径/参数/安装条件有代码与合成测试覆盖，桌面构建由 PR CI 验证；本轮没有 Windows 干净机真人操作、管理员安装、虚拟化/DLL 或模型业务验收。

## 合并与发布

代码合并和发版分开。本轮不打发布标签、不发布客户端、插件或 native pack，不部署服务器，不升级用户客户端。后续发版时应同时安排新版 pptx-runtime、诉讼可视化资源包及受影响插件；两平台干净机验收仍应覆盖断网、磁盘不足、非管理员、自定义路径、安装后恢复、损坏模型修复和取消。
