# 目录入口合并验收（dev-board #1582）

用户主要通过打开文件夹工作，要求移除重复的左栏「项目」面板。顶部在具名项目与无项目两态均提供完整目录搜索（最近使用优先）；欢迎页「更多」展开完整目录，保留改名、确认删除、团队案卷接收与跨设备目录。项目 ID、文件、对话、记忆和版本记录不迁移、不删除。

旧 `pane=projects` 深链在标签快照恢复后打开欢迎目录；旧面板命令同样转到欢迎目录；具名项目旧侧栏存储值迁回文件树，无项目无有效面板时收栏。对话模式打开完整目录会切到工作台，避免欢迎标签不可见。

## 实测

- `npm --prefix frontend run test:project-home`：1,995 项通过，包括目录搜索、当前目录激活、切换路径、旧入口、CLIENT 隔离和删除保存顺序。
- `npm --prefix frontend run check:nav:full`、`check:emits`、`check:locales`：通过，复用现有 20 语种令牌。
- 开发 H5 + Chrome 156，合成 40 个目录；`node frontend/tests/project-home/folder-entry-ui.mjs`（默认 5379，支持 `FOLDER_ENTRY_UI_BASE`）。所有 API 都拦截为合成数据，外部请求阻断，桌面桥仅提供取消文件选择的 stub。
- 实际页面验证：旧目录链接落欢迎页、项目面板消失、顶部和欢迎页都能搜到第 40 项；无项目侧栏宽度收为 0，顶部全部目录入口仍可用；桌面能力下欢迎页保留打开文件夹、跨设备目录组件；无 pageerror 或 null/undefined 项目请求。
- 截图人工核对：顶部菜单有界滚动、搜索输入与结果正常；欢迎页完整目录替换最近清单，避免两个长列表叠加。

## 保存与删除

切换仍走 `leaveWorkbench`，当前项目点击仅展开文件树，不重建工作台。当前项目删除复用同一出口：保存成功 → 版本确认 → 删除 → 离开。保存失败、确认取消、CLIENT 调用均不删除。目录组件在宿主返回 false 或抛错时不宣告删除成功。移除操作不影响磁盘文件的既有后端语义。
