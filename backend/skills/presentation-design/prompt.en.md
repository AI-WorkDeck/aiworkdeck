# Presentation design and reference matching

These are composable workflow steps, not a restricted tool list. Use only primitives actually available in the current host.

1. Understand audience, purpose, conclusions and evidence. Use existing sources without inventing facts or padding page counts. Group each claim with its evidence; place comparisons side by side, chronology on timelines and complex data in tables or charts. Page count follows reading needs. Density comes from organization, not tiny fonts. Combine related timelines, risks and decisions when they contain little information; do not spread them across slides merely to preserve a card layout. Clearly label synthetic, hypothetical or example material on the relevant conclusion and data slides, not only in notes, and never describe it as measured real-world results.
2. Learn supplied references before creating. Read fonts, sizes, weight, hierarchy, paragraph spacing, line spacing, indentation, page dimensions, background, master/layout and geometry. Inspect representative cover, content, table/chart and ending images. Record a concrete style specification rather than guessing from a style label. Keep references read-only; Word reference learning must not overwrite the project's default profile. Identify inherited, unknown and truncated information.
3. Compose read, locate, local text edit, typography, background/shape style, geometry and page structure primitives. Use observed identities and expected original text; refresh page order after structural edits. Read existing shapes after creating a slide. Reuse its title or placeholders, or explicitly remove them by exact identity before creating replacements; never overlay a second title. Never replace globally for one local change. A failed operation may have created content: read back before retrying.
4. Apply consistent palette, hierarchy, grid and margins. The supplied reference takes precedence over defaults. Adapt Word hierarchy and visual identity to slide reading while preserving clear, readable grouping. Whitespace must support comprehension; meaningful evidence and organization take priority over decoration.
5. Read back content and inspect actual rendered images for every output page. Use doc_export_pdf for the PDF needed by visual review; discover that tool first if unavailable. doc_restore_checkpoint discards this turn’s changes and is only for deliberate restoration, never a substitute for export or save. Compare reference and output images when applicable. Check clipping, overlap, contrast, alignment, excess whitespace, fragmentation and chart clarity. Re-render and inspect affected pages after fixes. Only inspected images count as visual verification; tool success or text extraction is insufficient. Disclose unavailable capabilities and unchecked pages. Fix visible clipping, overlap and material style mismatches. Optional polish must not trigger endless full-deck revisions or repeated checks of pages already verified. Each correction must address a specific unmet requirement. Deliver once those issues are resolved and affected pages pass review; optional suggestions must not create further rounds of tweaking.

When generating a PPT from a Word reference, finish learning the reference, then call slide_create_file to create and open the output BEFORE discovering other slide_* tools. Those tools are hidden while Word is active and become available after creation; repeated catalogue searches cannot reveal them before the switch. This is not missing capability and is not a reason to switch to image generation.

## Expressive presentation design

Choose a visual direction from the subject, audience and existing brand before composing pages. Avoid a universal navy card grid. Within consistent color, typography and rhythm, combine full- or half-bleed imagery, asymmetric columns, large statistics, charts with annotations, compact comparison tables and timelines. Vary adjacent compositions without changing the visual identity on every slide. Content pages must retain conclusions, evidence and necessary explanation.

Treat images as separate assets; keep text, numbers, legends and tables editable. Images and decorative shapes may intentionally extend beyond the canvas and be cropped at its boundary; essential subjects and text must remain visible. Background imagery needs space for text and an appropriate overlay or solid backing based on actual contrast. Specify purpose, aspect ratio, focal placement, negative space, palette and crop before using an available image-generation tool. Generate needed assets rather than rasterizing whole slides. Reuse suitable existing assets; never present generated scenes as evidence of real events or fabricated data.

Match charts to relationships: columns or bars for category comparisons, lines for trends, stacked charts or limited-category doughnuts for composition, scatter plots for correlation, and tables for precise lookup. Keep units, scales and series colors consistent; identify sources and meaningful baselines. Do not fabricate values or distort comparisons with decorative 3D effects. Prefer native charts; never claim an unavailable chart type was created.

Use short, restrained slide transitions to support narrative rhythm, usually consistently across the deck with changes at meaningful section boundaries. Follow explicit reference motion or user requests. Do not default to automatic slide advancement or animate every object. Static exports cannot demonstrate motion: verify saved/reopened transition settings and actual playback separately, never claim animation passed from PDF screenshots.

Visual review must distinguish intentional bleed from accidental overflow. Cropped decorative imagery can be valid; clipped text, data labels, legends or essential subjects still require correction. Compare inserted images with their sources to confirm recognizable subjects, intact proportions and undamaged content. Smearing, stripes, mosaic corruption or cropping away the entire image cannot pass as intentional bleed. Check that design reflects the content, avoids repetitive card layouts, has a clear visual focal point and preserves accurate data, units and editability. If image generation fails, retain completed pages and identify missing assets; do not claim unrelated placeholder images complete the task.

When available, call image_generate_asset once per planned asset with a stable requestKey, then image_get_generation with its generationId until completed. Reuse the returned db_id with slide_add_image; never submit a new paid generation merely because polling or insertion failed. Read slide dimensions first, set cover/contain and focalX/focalY deliberately, and send background imagery behind editable content. Use slide_add_chart for native data, slide_format_chart for palette and readable labels, and slide_set_transition for slide motion; these are separate operations and can be combined with text, shapes and tables. Read the target page after partial failures before retrying.
