## 文件整理与目录归档工作流

本轮任务是对项目中的文件与文件夹进行结构化梳理、分类命名或目录归档。请严格遵循以下工作流：

1. **先盘点目录全貌，再抽样识别不明文件**
   - 先用 `list_files` 或 `search_project_files` 查看当前项目的目录树与全部文件名。
   - 文件名已清晰表明性质的（如「公司章程」「营业执照」「借款合同」），直接按文件名归类，不要逐份全文读取浪费步数。
   - 仅对文件名含糊（如 `scan001.pdf`、`新建文档.docx`、`附件1.pdf`）的文件用 `extract_file_text` 抽读开头片段以识别文书性质、签署主体与日期。

2. **分类维度与目录结构设计**
   - 若用户已指定目录规范或律所底稿标准，严格按用户给定目录执行。
   - 若用户未指定，按项目材料性质选择最贴合的一套结构（层级不超过 2～3 层，避免空壳深层目录）：
     - **尽调 / 非诉项目**：`01-主体资格与公司治理`、`02-业务与重大合同`、`03-资产与知识产权`、`04-财务税务与融资`、`05-劳动人事与涉诉`、`99-产出报告与工作底稿`；
     - **诉讼 / 仲裁案件**：`01-主体与管辖材料`、`02-起诉答辩与程序文书`、`03-己方证据材料`、`04-对方证据与质证`、`05-检索与代理意见`；
     - **合同交易管理**：按「主协议 / 附属及担保协议 / 履行与交割凭证 / 往来函件」或按交易对手分夹。

3. **执行准则：先建目录、再走 `move_files_batch` 一次批量提交**
   - 若用户要求「仅给归档建议」，输出清晰的【原路径 → 建议目标目录/建议文件名】对照表供用户确认。
   - 若用户要求直接整理，先调用 `create_folder` 建好目标文件夹，随后**必须**使用 `move_files_batch` 在一次调用内批量完成移动/重命名，严禁对十几份文件逐个调用单文件移动。
   - **安全底线**：不主动删除任何业务原件；确属重复的空白临时文件需清理时，仅可移入回收站（`move_to_trash`）并在最终汇报中列明。
