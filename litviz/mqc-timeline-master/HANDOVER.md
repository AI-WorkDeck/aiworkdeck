## 1.2 v1 是什么（务必读完这一节）

v1 是仓库作者缪奇川律师已发布的 skill，叫「诉讼可视化重画」。它做的事是：
**用户给一张已有的图或一份结构化描述，它按一套固定的视觉规范重画出来。**

v1 已经解决了很多问题，而且解决得比新写一遍更好。它包含：

**七种图种**：编号型时间轴 `numbered_point_timeline`、日期型时间轴
`dated_point_timeline`、期间型 `proportional_gantt`、流程图 `graphviz_flow`、
关系图 `graphviz_relation`、关系树 `relation_tree`、对比表。

**三档视觉模式**：奇川风（灰阶 + 唯一深红，默认）、歸藏风、白描（纯黑白线稿，
可影印、进卷宗）。三档**共享同一套几何与同一套信息**，只换配色。

**一套冻结的视觉规范**，在 `references/visual-style.md` 与 `references/STANDARDS.md`。
最要紧的几条：

- 卡片填充 `#F3F4F6`、描边 `#D6DAE0` 1px。**只有深红块 `#991B1B` 无框**，块内
  文字用白色。
- **唯一强调色。** 一张图只能有一处深红；标两处等于没标。
- 字号取自 `common.FS`：`doc_title` 30、`node_title` 17、`subtitle` 13、`note` 12、
  `num` 22。**渲染器里不许写死字号。**
- 期间条**直角、永不圆角**；标签**放在条内**居中，装不下就右对齐紧贴条的左边缘；
  **红条内的标签用白字**。
- 日期型的轴是**浅灰色带，带一把诚实的刻度尺**（年刻度，跨度短时用年月，自动选）；
  刻度线画在真实单位边界上、贯穿色带；年份标签**居中在每个单位区间内**。
- 日期型**没有圆点**（原文：`No node dots — the connector meets the bar edge`）。
  编号型才有圆点，深色实心带白色数字。
- 标题区**只放图名**。
- **密集或无日期的事件用编号型**（原文：`use the numbered form for undated/clustered
  events`）——这一条是规范里本来就有的，不是后来发现的。
- 审计摘要留在回复里，**永不画到图上**。
- 落款默认关闭。印刷字号下限 **8pt**。

**v1 的实现在 `plugins/mqc-nlv/skills/mqc-litigation-visual-redraw/scripts/`**：
`common.py`（字阶、色板、`wrap`、`text_w`、`parse_date`、`load_map`）、`lint.py`
（版面检查）、`render.py`（总入口，含 `_png_safe_svg`、`svg_to_png`、`to_monochrome`、
以及一个会报错的替换辅助 `_sub(need=True)`）、各图种的 `render_points.py` /
`render_dated.py` / `render_spans.py` / `render_flow.py` / `render_relation.py` /
`render_tree.py`，还有导出器 `export_pptx.py` / `export_drawio.py` / `export_vsdx.py`。

**v1 的回归是 `tests/run_checks.py`，136 项守卫 / 149 条断言。** 本地跑会有一条
gallery 逐字节比对失败（容器字体栈与 CI 不同），那是已知环境差异，本地绿的标准是
**148/149**。

**v1 处于冻结状态。** 本会话对它只做了一处非功能修正（README 里 126 改成 136），
其余一律不动。要改 v1 需先解冻。

## 1.3 本 skill 要做什么

v1 的输入是**已经整理好的结构化描述**。本 skill 补它前面那一段：

**律师丢进来一份判决书 PDF，输出一张时间轴图。**

即「读材料 → 语义地图 → 出图」，出图尽量复用 v1，读材料是全新的。

定位是**只做忠实模式**：把材料里发生过的事按时间排出来，不做事件评价、不做法律
分析。分析能力若要做，是仓库里第三个独立的 skill。

## 2.2 语义地图 schema v2

在 v1 的 schema 上做**纯增量**扩展。`schema_version` 扩成 1 或 2；`layout` 加了
`vertical_single_column`；event 加了 `unit_type`、`quote_depth`、`lane`、`time`、
`head`、`body`、`items`、`index_note`、`source`、`head_short`；顶层加了 `medium`、
`frame`、`scope`、`groups`、`stipulated`、`lanes`、`conflicts`、`residuals`、
`documents`、`checkpoint`。

**「纯增量」这句话由测试守着**：v1 的八个示例地图必须通过 v2 校验器且零错误，
这是 `tests/run_checks.py` 的第一段。

写了 24 条守卫，每条都配一个「故意改坏必须报错」的测试，跑出来是
`24/24 条守卫确认可失败`。

**`frame` 是刻意藏起来的。** 作者提出过一套「新诉讼可视化」的三维坐标理论
（阶段 × 受众 × 内容），但他的第二篇主力文章还没发表，所以理论只进骨架、不进面子：
`frame` 三个字段照记，但**不叫坐标、不进用户视野、不上图、不写进公开文档**，只在
地图和索引里躺着，等文章发出后接上。用户看到的是三个具体问题（现在到哪一步 /
这张图给谁看 / 要画哪一段），答完这三题 `frame` 就填满了。

## 2.3 拿真实材料跑，撞出四类问题

作者提供了三批真实案件材料（**均为未脱敏的真实卷宗**）：

- **第一批** 一份北京的合同纠纷判决书，32 页。
- **第二批** 一份浙江的股权投资对赌纠纷判决书，11 页。
- **第三批** 一个买卖合同纠纷案的四份材料：起诉状、民事反诉状、原告证据目录、
  被告证据目录。

撞出来的问题事先一件都没预料到：

**页脚劈进词中间。** 第一份判决书有 32 处 `- N -` 页脚，其中 **24 处被 PDF 抽取器
塞进了词的中间**。所以页脚必须在任何读句子的动作之前清掉。

**数字换行吞掉日期。** 原始抽取里是 `…延迟了数月。」2017\n年 7 月 24 日…`，换行落
在数字和「年」之间。软换行合并规则原来要求换行两侧都是汉字，不触发，句子被切开，
`2017` 留在上一句，**那个日期连正则都扫不到**。而那条微信恰是被告主张利润被挪走的
核心证据。补上「汉字↔数字」双向后，完整日期从 13 个涨到 27 个。

**表格列串行。** 原告证据目录是表格，`pdftotext` 抽出来的顺序是：证据 4 的名称 →
证据编号 5 → 证据 5 的名称 → 类型 → **然后才是证据 4 的内容**。任何按顺序读的程序
都会把「中标通知书」和「被告作出书名说明」当成同一行。**这比漏事件更糟：图上会出现
一个材料里不存在的对应关系，而它看起来完全正常。**

**扫描件无文字层。** 四份材料里两份（被告方的两份）是纯扫描件，文字层只有 2 字节。
按原设计第一版不做 OCR，于是被告方材料完全读不到（**已解决**，见本节末与 ADR 0001、
0002）——**而这个案子的争点全在两方陈述
的冲突上**：同一次验收，原告说因质量不符未通过、被告说被专家无理拒收；原告说被告
未提书面异议、被告说数次据理力争并书面投诉纪检。

**由此定的规矩**：对方提交的材料几乎总是扫描或拍照的。不读图就永远只能看见一方，
而只看见一方的时间轴恰恰是最危险的产物——它看起来完整，实际是单方陈述。所以
**让模型直接读图**（不引 OCR 依赖），但图像来源的事件单独标记
（`source.medium = "image"`），不参与逐字核验、不进离群检测基准，且交付时必须声明
哪几份材料没有文字层、有几个事件出自读图。这条有守卫（数目不符即报错，上线时当场
抓到一次数错）。

**读图那一半后来做成了（ADR 0001、0002）。** `scripts/read_image.py` 三步 —— 探测
（**逐页量可读字符**，不是看 `pdffonts` 有没有字体，真材料上有反例）、150 DPI 栅格化、
模型逐页看图；仍然不引 OCR 依赖（poppler 自带命令，各家 harness 都跑得动）。
读图所得写成**转写稿存档并作为材料**进管线，于是子序列与 `raw` 逐字这套判据原封不动生效
（实测 20 页纯扫描件 7 条正文全过）。完备性对账在这条路上会变成自证，所以另加外部锚：
页数账 + 材料印着的编号总数。

## 2.4 冲突有两种，这是材料教的

原设计只考虑**日期冲突**（同一事实、不同日期）。买卖合同案教了另一种：

**性质冲突**——日期完全一致，两边对同一件事的描述相反。所以 `conflict.kind` 有
`date` 与 `characterization` 两值，且守卫要求冲突的任一方都必须还在 `events` 里，
**删掉一方等于替用户和解了争点**。

## 2.5 视觉形态：最长的一段反复

这一段占了整个会话最多轮次，大部分是在改自己的错。

### 2.5.1 卡片结构：从「片段堆叠」改成「一个标题行 + 一个正文块」

最初设计把句子分成 L1 到 L5 五层，按介质预算从 L1 往下填。渲出来是**一摞互不相连
的片段**：一行主句，底下三行各自是原句里抠出来的短语，字号不同、语气不连。作者的
评价是「不是法言法语，是一堆剪报」。

改成：**卡片只有两个成分、两种字号**。一个标题行（17px 加粗）、一个正文块（13px），
正文块二选一——自然段或编号列表，**不得并存**；用哪种由原句自身结构决定（原文本来
是并列条项就用列表，否则自然段）。图标、旗标、第三种字号全部取消。审计性说明
（离群观察、引用层级、推定依据）撤出卡片，写进 `index_note`，只进溯源索引。

正文一律按法言法语撰写，**不许出现破折号与引号**（书名号除外），有守卫。

### 2.5.2 横向多层：从「一方一边」改回 v1 的交替，再扩成多层

走过一段大弯路：为了做「原告在轴上、被告在轴下」，把 v1 的上下交替机制拆了。后果是
**同侧连续事件必须逐个占槽**，原告连续八个一来，卡片压到 71px、每行 2 字。同时还
改坏三处 v1 本来对的东西：轴从细发丝线变成 16px 灰粗带、编号圆点从深色实心带白字
变成小圆点、日期从卡片内第一行挪到轴两侧去挤。

作者评价「彻底是胡画了」，判断准确：**交替能让相邻卡片横向重叠，分方不能，这一条
差别就是可用宽度的一半。**

改回 v1 形制后，扩展方式是把 `band` 从两值扩成每侧多层。层数由事件数推，但阶梯只是
起点——**排不下自动加层，加到三层还排不下就拒绝**，因为事件数说不清密度（八个均匀
分布两层够，八个连着就不够）。

层的选择**优先贴着上一张卡的层**（作者称之为正弦排布），同距时偏向靠轴：密集段
走成 0,1,0,1，永不跳两级；稀疏时仍全部落回第 0 层，图不会白白变高。固定模式做不到
最后这一条。

### 2.5.3 引线穿卡：三个自己造出来的假约束

多层交错的本质是用卡片横向重叠换宽度，卡片一旦重叠，较高层的引线必然穿过较低层的
卡。用「引线先画、卡片后画」让它被遮住，但线从卡的上沿钻出、下沿钻入，看上去就是
穿过。**遮盖解决叠压，解决不了穿越。**

加了「不许卡片横向盖住同侧邻居的圆点」之后容量从 20 掉到 8。查下去是三个自造的
假约束：

1. **净空重复计算。** 占位区间写成 `圆点 ± (卡宽/2 + 净空)`，两侧各加一次，于是两张
   卡之间实际要求 28px 而不是 14px。
2. **穿越校验写成了双向。** 一张卡的引线只从轴升到自己那一层，不会再往上，所以
   **低层的卡挡住高层的圆点才算穿越，反过来无所谓**。双向校验把限制加了一倍，凭空
   吃掉三分之一可用卡宽。
3. **边界相等。** 9 个事件时卡宽 190px、同侧间隔 218px，`190 + 28 = 218` 正好相等，
   浮点加半像素吸附一抖就判失败。

修完之后：**单方 A4 横版上限 12 个，11 个以内根本不用分层**——上下交替后同侧事件
天然隔两格，一层就排得开。之前那个「三层」是自造的假象。

三层机制保留作兜底，但实测从未在真实材料上触发；它只在两方对读且某一方连续出现
七八个事件时才需要。

### 2.5.4 竖线粗细不均：从「记得吸附」改成「不可能忘」

1.4px 的线压在整数坐标上会横跨两个设备像素，压在半像素上才落在一个里。

第一次修在各处手动吸附，**失败了**：吸附公式 `round(v*2)/2 + 0.5` 本身有 bug
（`v*2` 取整后是偶数时又落回整数），而且新写的渲染器不会自动继承。

正确的修法是抽出 `scripts/geom.py` 里的 `hairline()`，**吸附逻辑在函数里，调用方
绕不过去**；再加守卫扫所有 `<line>`，常数坐标必须落在该线宽对应的相位上，源码里
不许出现直接拼接的 `<line`。守卫上线立刻抓到纵向渲染器有 8 条从来没吸附过。

### 2.5.5 圆点与数字：从两张手调表改成一个公式

原来两张表：横向 `{1:12, 2:10, 3:9}`、纵向 `{1:9, 2:8}`。作者要求「形成一个固定
稳定的数学模型，让它能自适应调整，而不是每次都手动看」。

现在是 `geom.dot_metrics(spacing)`，一个公式：

```
2R ≤ 0.45 × 相邻圆点间距        圆点最多占间距的 45%，上下限 8 到 13
字号 = R × 1.05
基线 = 字号 × 0.36              数字无下伸部的标准光学中心
```

只有 0.45 那个占比是判断，其余全是比例。守卫要求渲染器里不许出现 `DOT_R_BY` 或
自立的 `NUM_RATIO` / `NUM_BASE`。

**居中这件事绕了三圈，值得记：** 第一次用「墨行首尾中点」量得偏差 -0.5px，据此调大
基线系数；第二次换「墨量重心」量得 +0.4px，**方向相反——第一个量法本身带半像素
偏差，按它调是在追假信号**；第三次才发现根子是横向的圆心被吸附到半像素、纵向的
没有，**两个方向的圆心不在同一相位**，同一个系数当然对不齐两边。现在圆心统一走
`geom.snap_centre`，并有守卫。残留 0.5px 以内（纵向小圆点档 1.1px）；系数从 0.34
扫到 0.40 试过残差纹丝不动，说明它来自字号取整不来自基线，已停手并在注释里写明
原因与已花掉的代价。

### 2.5.6 省略号：一次原则性的错误

为了填满 311px 的卡片，把放不下的完整标题截断、补了个省略号。作者的评价是
「放一个省略号，这是法律人不能容忍的事情」。

**这个批评比表面更严重**：截断等于从材料里删字，还留个记号说「这里有东西你看不到」，
跟 verbatim 规矩（只许删减不许改写）直接冲突——**截断本身就是一种改**。

正确做法是让卡片让步、不让文字让步：收紧卡片内部尺寸（上下内边距 13→10、日期与
正文间隙 8→5、行距 24→22、标题区 88→76、尾部 48→28），20 个完整两行卡收在一页内。
守卫：**图上出现省略号直接报错。**

顺带炸出一个旧 bug 复发：**数字被拆行**（「转账4万元及9|300元」、「485000|元」）。
这个 bug 修过一次，补丁写在横向渲染器里，还在注释里写了「这属于共享内核，以后要
搬走，不能留两份」——**结果没搬，纵向渲染器从来没拿到这个修复**。现在
`geom.wrap_atomic` 一份共用，原子正则覆盖完整日期（`2024年12月1日` 原来会被拆成
`2` 和 `024年…`），守卫要求渲染器不许直接调 `wrap()`。

### 2.5.7 泳道不是图种

作者的判断：「泳道不需要单独分出一个分类，它只不过是时间轴中的一种表现形式，是一个
隐藏的分类，不需要用户知道你选了这个分类。」

照办：`layout` 枚举里删掉 `swimlane_timeline` 与 `two_party_horizontal`。`lanes`
保留但含义改成「有没有对立主张方」。**分几层、几列、谁在哪一层、圆点多大，全部由
脚本按几何算，不进语义地图。**

侧标签的规矩：**有 `lanes` 就是有意义的分布，必出侧标签；没有就是纯为省空间的交替，
不许出侧标签**——否则等于宣称一个数据里没有的区分。

### 2.5.8 纵向左右对开：容量与文字量双赢的那一档

A4 竖版（当时 722×1092，现为 700×1096）的实测对照：

| 排布 | 一页容量 | 卡宽 | 每行字 |
| --- | --- | --- | --- |
| 纵向单列（轴在左） | 9 | 508px | 29 |
| 横向多层（A4 横版） | 12 | 138px | 6 |
| **纵向左右对开（轴居中）** | **20** | **311px** | **16** |
| 纵向每侧两列（2×2） | 30–32 | 152px | 7 |
| 纵向每侧三列 | 32 | 88px | 3 |

**2×2 是拐点**，不是因为容量最大，而是再加列不再涨容量——步距已被圆点直径顶死在
30px。

列数选择：**按页高预算选，不按「能不能排开」选**。一列总能排开（步距会自己拉长，
图变高而已），所以问题不是「能不能」而是「装不装得进一页」。一列装得进就用一列
（卡片最宽），装不进升两列，两列还装不进就取**最矮的那个**去分页。最后这一条第一版
写错了（回退到列数最少的），结果 14 比 6 分侧的案子用一列排出 2010px、两页，而两列
只要 1462px。

纵向的步距下限有三条，都是量出来的：圆点不相碰、同列两卡不重叠、**内列的卡不得在
纵向上盖住外列事件的圆点**（横向引线穿卡，与 2.5.3 同理，方向不同）。同列间距要按
**同侧最长的连续段**算，不能按理想交替算——买卖合同案原告连续八个，按交替算的公式
当场失效。

### 2.5.9 分页

长图与分页是**一份排布的两个输出**。长图保持等距、**不画任何辅助线**（作者：
「律师不可能拿着辅助线去裁剪再打印」）。分页是另一个输出，同一份排布重新按页发
一遍，只有在分页里才允许调整间距（读者不会把两页并排看）。

三条规矩都有守卫：断点绝不落在卡片内部（会被切的整张推到下一页）；每页重复表头与
两侧主张方名称，第二页起标「接上页」，且续页表头与首页同字号同基线；**编号绝不
重排**（第二页从 15 号开始），否则图和溯源索引对不上。

**标题区只放图名**这一条在分页里犯过第二次：一度放了页码、页数、本页日期区间。
已撤，并加守卫。页码要标识就放文件名。

## 2.6 日期型：绕得最远的一段

### 2.6.1 从零重写，丢掉了一半规范

第一版日期型是从零写的，而且是照着一张网上看到的参考图在改。结果：**没有刻度尺**
（一个按比例的轴不带刻度，读者无从判断任何位置代表什么时间）、**擅自加了圆点**
（v1 日期型明文 `No node dots`）、卡宽从 214 改成 168、还自创了「空白占比」与
「簇内负载」两个判据——而 v1 的 SKILL.md 原文就写着
`use the numbered form for undated/clustered events`。

作者的评价：「你就是看了一下我上传给你的那个图片，人家做那个时间轴，瞎改了一版，
一直在按照那个版搞我的原文。」判断准确。

**结论：从已有的答案出发，丢不掉东西；从零开始，会把想清楚过的问题重新答一遍，
而且答错。** 现在 `render_dated_v2.py` 是从 v1 的 `render_dated.py` **逐字复制**
来的，只加断裂，其余一律不动。

### 2.6.2 簇：一个应该撤掉的发明

中途发明了「同一时点共用一个圆点、卡片沿轴展开」。作者否掉：「时间型的那种是不能
分簇。簇那种方式是绝对不对的。」

**这个否定在道理上是对的**：在按比例的轴上，两个相隔一天的事件本来就在同一个位置，
把它们的卡片沿轴散开，等于把每张卡放到一个它的日期并不在的地方。现在撞点直接拒绝，
指名哪几对、相隔几天，让用户改用编号型。

### 2.6.3 日期型的真实适用范围

八份地图跑下来，**没有一份「合适」，五份不合适、两份勉强**。原因高度一致：真实
案件里事件总是成簇的（签约、付款、催告、回函天然挨在几天之内），而按比例的轴不能
表达几天之内的先后。

作者的判断：「日期型时间轴适用的范围可能没那么大，只有在需要展现日期的情况下才会
用到，而更多的是像我们刚刚做的那种编号型。」

作者另一个很有价值的观察：**单位可以是年、月、甚至日，所以「短期」不是障碍。**
v1 原来只有年和月两档、月档下限 66px，三周的验收争议按月刻度只有一格，画不出来。
所以加了周刻度档（`WEEK_MIN_PX = 52`）。

但试下来短期案件仍然排不开：买卖合同案 134 天、八个精确时点，周刻度轴宽 1092px，
4 月 25 日到 28 日只隔 24px，而同侧两张卡需要 230px；再下探到日刻度要 1813px，
A4 横版也装不下。**所以「排布不冲突」是独立的硬条件，不能靠细化单位绕过去。**

### 2.6.4 碰撞门禁的两条

原来只看圆点是否重合。扩成两条：圆点要分得开（20px），**同侧相邻的两张卡也要放得
下**（卡宽 + 净空）。后者才是真正咬人的——29 天的间隔看着宽松，卡片却装不下。

拒绝理由也改成说实话：原来写「几乎落在同一位置」而实际相隔 29 天，那是自相矛盾。

## 2.7 期间型

### 2.7.1 纵向期间型不做

做过一版纵向双侧期间型，撤掉了。理由不是没调好，是**形态本身与规范冲突**：期间需要
沿轴伸展出长度，而规范要求标签放在条内；竖过来后条只有 26px 宽，标签物理上进不去，
只能排到外面，于是同时破了「标签在条内」和「红条内白字」两条。

### 2.7.2 深红只标已发生的事实

一版图里把「2016 年度业绩承诺考核期」标了深红。那是协议约定的窗口，不是已发生的
事实。新加的守卫当场报错。改到「逾期未交付期间」才对——它既是事实、也是争点所在。

`unit_type` 因此引进期间：**约定期间画浅色、永不用强调色。**

### 2.7.3 期间型的四条启用条件

有 spans、不超过 8 段、至少一段是已发生的事实而非全是约定、**至少两段重叠或包含**。
最后一条是核心——期间型的价值在于重叠本身，若只是罗列时长，编号型更清楚。

### 2.7.4 标签放右边，不放左边

v1 的做法是「装不下就贴着条的左边缘右对齐」，那是给「保证期间1」这种四五个字的标签
设计的。遇到 245px 的长标签，最初的补法是**把左边距撑开去迁就标签**——于是轴线只能
从更靠右的地方开始画，**标签底下那一大片纸没有轴**。

作者指出后改成：**让标签动，不让边距动**。左边距退回 60px，溢出标签一律放在条的
右侧、必要时折行。中间还错过一次：第一版写「哪边空间大放哪边」，结果同一张图里标签
左右混着放、眼睛来回跳；改成一律优先右侧，只有右边连折行都放不下才退到左边。

### 2.7.5 轴要有前后余量

第一段期间与轴起点齐平，看着像时间从那一年才开始存在。**这不只是好看的问题——轴的
起点和第一段期间齐平，等于在说这之前什么都没有，而材料并没有这么讲。** 现在前后各留
一整年。

这个改动连着修了三处：加余量后两个年份标签重合（断裂逻辑把新加的余量当成了该压缩的
空白，整年被压成零宽——**余量不该参与断裂判定**）；画布宽度没跟着涨（宽度公式漏算
了实际左边距）；断口标注与最后一条期间的日期压在一起。

## 2.8 断裂（axis break）

作者从参考图里点名要学的唯一一样。做法按作者指定：**与底色同色的平行四边形盖在
色带上**，两侧各一道斜线。

**判据是两条，不是一条**：必须同时「占跨度 18% 以上」且「绝对超过 400 天」。只看
比例的话，十个月的迟延案里那七个月的间隔会被压掉，**而那七个月正是那张图要讲的事**。

**同一个手法在两种形态上不能照搬**：平行四边形在日期型上成立（轴是实心灰带，切一块
纸色出来），在期间型上不成立（轴只是一条刻度线，没有实心可切，盖上去什么也没盖住）。
期间型的断口只留两道斜线加文字说明。

**断裂之后轴就不是等距的，而且应该看得出来。** 原来把超长空白按比例截断，它看着还是
个普通间隔；现在给它**固定的小宽度**，压缩过的那一段明显短于正常段。

**断线尺寸**（作者最后一轮的要求）：日期型只比色带略宽（`SLANT, HALF = 4, 5`，上下
各出 2px）；期间型缩短 50%（`SL = 4`，纵向 ±7）。两段长度必须一致——原来不一致是
因为两端坐标从不同基准算出来的。有守卫（两段长度差 >1px 报错、长度 >30px 报错）。

**断口覆盖的那一格年份标签要省掉，不要盖住。** 第一版把压缩区间内的年份全省了，
结果 2016 到 2020 一个不剩、读者失去方位，**比原来那个半遮的更糟**；现在只省断口
实际盖住的那一格。

**A4 横版是硬上限。** 期间型原来 1398px，超出 221px。横向图超宽的后果是打印时被
缩放，直到跌破 8pt 下限，所以**让刻度间距让位，不让纸张变宽**。两个渲染器现在都
封在当时的 1177，有守卫。（**现在的上限是 `paper.LAND_W` = 1070**，守卫也已改成从 `paper` 现取；1177 是白边改档之前的数。）

## 2.9 形态路由器

作者的要求：「把那些内容过来之后，分配到合适的图形类型当中，这才是一个很好的东西。
而且这个机制很重要，很重要。」

原则沿用 v1 的一条：**图种是校对不是点菜**——脚本出候选并给出机械依据，律师校对；
把做不到的选项摆出来让人选是骗人。

`scripts/propose_layout.py` 的输出直接就是 checkpoint 第一问的样子，**每条排除都带
机械理由**。十份地图跑下来：编号型七份、期间型两份、日期型一份，这个分布是判据算
出来的，不是定的。

**两个错是探针抓出来的：**

1. 原来的「长间隔」判据要求一年以上，**直接把最该用日期型的迟延案排除了**（总跨度
   323 天，七个月的迟延就是全部论点）。改成看相对关系：一段间隔要明显长于其余
   （≥2.5 倍于其余的均值）。
2. 「间隔无主次」那条**写反了**：四个事件每隔 100 天等距分布，每段都占跨度三分之一、
   都超过四分之一，判据放行。它该要求「有一段明显长于其余」。

**而这个错误用真实地图是测不出来的**：拿真实地图把「三天内」阈值从 1 改成 99，结论
纹丝不动——那份地图有 17 个事件，下一条「超过 8 个时点」照样挡住它。**判据之间有
冗余，单改一条测不出来。** 所以守卫有两层：七份真实地图钉住整体判断，**五个合成
探针各自钉住一条判据**。

路由器与渲染器**必须算同一件事**：一度路由器说「三天内相邻」、渲染器说「轴上不足
20px」，这会导致路由器推荐一种形态而渲染器接着拒绝画它——最糟的那种不一致。现在
路由器按渲染器的算法预测轴宽（每年 118px、每月 66px）。

## 2.10 读材料（本会话最后完成的一段）

### 2.10.1 判决书 PDF 里没有段落

第一份判决书 832 行**只有 70 行以句号结尾**。每一个换行都是排版折行，不是段落。
最初判断「规范化把段落边界吃掉了」，**那是错的——那个边界从来就不存在**。

段落边界要**按行尾句末标点重建**。另外抬头那几行（法院名、案号、当事人）不以句号
结尾，全被并进第一个真正的段落，于是「原告某某起诉称」跑到第三十几个字，任何开头
匹配都够不着——需要「短行（≤25 字）且不以逗号顿号结尾者自成一段」这条规则。

### 2.10.2 判决书不一定写「本院查明」

第一份判决书从头到尾没这四个字。它靠一句固定开场白起头（「当事人围绕诉讼请求依法
提交了证据，本院组织当事人进行了证据交换和质证。根据当事人陈述和经审查确认的
证据……」），靠一句固定收尾结束（「以上事实，有当事人提交的证据以及本案庭审笔录
在案佐证」）。

**起点可以没有标题，终点几乎总有——所以查明块是靠终点往回定的。**

这一条推翻了前面几轮的一个假设。此前把「按叙述块取材」当成默认取材单位、当成泳道的
行、当成 checkpoint 的选项，那些都建立在「判决书有稳定四块结构」这个错误假设上，而
那个假设是从第二份判决书看来的。现在四份材料（两份真实判决书 + 两份人工 fixture）
叙述块全部识别正确。

### 2.10.3 切句：342 句是对的，446 是错的

之前记的 446 句是老原型按分号多切的。现在切句拼回去跟规范化文本**一字不差**，做成了
守卫（这是整套召回保证的地基）。

### 2.10.4 模型三步：先写校验器，再写指令

那三步要读懂意思，无法确定化。**能确定化的是检查**：如果模型的每个断言都可以对句子
核验，错答就变成一次检查失败，而不是一张错图。**模型可以答错，但不许悄悄答错。**

所以**先写 `scripts/check_model_output.py`，再据它写 `references/model-steps.md`**
——校验器决定指令必须要求什么；反过来写会出现指令说得漂亮、校验器管不住的情况。

三条核心检查：

- **逐句判定必须一句不少。** 检查会数句子条数与判定条数。这条挡的是一种看不出来的
  错——如果只要求「把事件挑出来」，一个跳过四十句的模型和一个读完四十句认定没有
  事件的模型，**输出完全一样**。
- **时间表述的 `raw` 必须在原句里逐字查得到。** 挡的是推算：「次年初」写成
  `2017/1/1`，输出里看不出材料从没这么说。另外判 `exact` 必须句子里真有「日」，
  「2020 年」判成 `2020/1/1` 会被拒——那是把年份当成一月一日。
- **卡片每段文字必须是原句的子序列。** 这是「只许删减不许改写」的可检形式：子序列
  意味着删词可以、换词不行、调顺序不行。

九种违规输出逐个试过全部拦住，包括最难的两种：改写时间表述、片段顺序颠倒。

**加了一条防漂移守卫**：指令与校验器会分开演化，改紧一处忘了另一处，模型就会交出
过不了检的东西且没有信息说明为什么。守卫同时验两件：校验器对九种坏输出必须报错、
指令必须提到校验器要求的每一个字段（把 `anchor` 从指令里删掉试过，立刻报错）。

### 2.10.5 拿真实材料试出来一件事

第一份判决书查明块 37 段切出 240 句，判前 30 句发现**大量句子是合同条款原文**
（第二条经营期限、第三条经营目标、第四条利润分成、第八条乙方义务）。

这印证了此前测出的数：**约定条款在查明部分占比极高**——第一份判决书 62 处绝对日期
里约 28 处、45% 是约定条款型。所以「合同条款不是事件」这一条在指令里必须写在最前面、
写得最重，它是数量最大的一类非事件。

## 2.11 脱敏

作者的规则：**给的材料是真实不脱敏的，但仓库里不能留下任何来自这些材料的东西；
脱敏后的可以留，脱敏前的一个字不留。**

**脱敏是维护者的工作，不是这个 skill 的功能。** 律师拿自己的卷宗跑自己的图，当事人
姓名、身份证号本来就该在图上，那是他的案子。此前一度把维护者的约束当成用户的约束
（说过「拿真卷宗跑之前必须有脱敏门禁」），那是错的。

扫仓库发现**已经漏了**：三份示例地图的当事人名称脱敏了，但 `source.quote` 里的逐字
引文原样抄进去，两位当事人真名、法院辖区、鉴定机构全在里面。**换主体名不等于脱敏，
引文才是漏的地方。**

`tests/check_anonymised.py` 按模式扫（十八位身份证号、统一社会信用代码、手机号、
案号、出生日期、户籍地址、住所地址），**不按名单扫**——名单只能抓住写的人记得的
那些名字。

fixture 里也不要写形似案号的东西。守卫按模式判、分不出真假；**让它去分辨真假，它就
会开始漏真的。**

# 第四部分 · 坑，按重踩代价排序

## 4.1 不要从零重写已有的渲染器

见 2.6.1。从零写过一次，无声丢掉了刻度尺、擅自加了圆点、卡宽被改、还自创了规范里
本来就有的判据。**从已有的答案出发，丢不掉东西。**

## 4.2 改代码前先 grep，不要盲用 str.replace

`str.replace` 匹配不到就静默跳过。本会话咬了五次以上。最典型的一次造成两个看起来
毫不相干的症状：**卡片文字颜色变淡、卡片下方多出 25px 空白**——同一处替换失败，
卡高按新行高算而文字按旧行高排。

改法：先 `grep -n` 确认目标存在，或用会报错的工具改。v1 的 `render.py` 里有
`_sub(need=True)`，抽内核时把它一起抽出来。

## 4.3 加了守卫不等于守到了

给「主张方标注居中」加过守卫，然后故意把标注挪偏 40px 去验——**守卫没报错**。原因是
渲染期守卫只检查渲染器直出的图，而**分页产物走另一条路径，根本不在被检查的集合里**。

**每加一条守卫，必须故意改坏一次确认它会失败，并且确认改坏的那一处真的被它看着。**

## 4.4 判据之间有冗余，单改一条测不出来

见 2.9。每条判据要配一个恰好卡在它身上的合成探针。现在有五个，形状是挑过的
（「同侧卡片放不下」那个专门挑了圆点分得开、卡片放不下的形状）。

## 4.5 验证工具本身会出错

批量改坏测试的脚本把输出按 `=== 读材料` 切开再按 `===` 切，而分节标题里本身带
`===`，切出来是空段，于是**四条守卫明明报错了却数成 0**。

**验证工具出错比被验的东西出错更隐蔽**，因为它给的是「一切正常」。

## 4.6 换主体名不等于脱敏

见 2.11。引文才是漏的地方。

## 4.7 判决书 PDF 里没有段落

见 2.10.1。

## 4.8 判决书不一定写「本院查明」

见 2.10.2。

## 4.9 同一个视觉手法在两种形态上不能照搬

见 2.8。平行四边形断口在日期型上成立，在期间型上不成立。

## 4.10 A4 横版是硬上限

见 2.8 末。让刻度间距让位，不让纸张变宽。

## 4.11 断裂之后轴就不是等距的

实测过：一个错分的约定条款日期恰好掩护了一个真实笔误（2015 年应为 2021 年），

只陈述观察（「距最近事件 1662 天」），不猜原因。

# 第五部分 · 已定的规矩，不要重新讨论

**重新讨论这些会浪费大量轮次，而本会话大部分轮次就是这么花掉的。**

## 5.1 图种与路由

**编号型是主力。** 八份真实材料里没有一份适合日期型——诉讼事件天然挤在几天之内，
按比例的轴表达不了几天。这是量出来的，不是偏好。

**日期型只在同时满足时才用**：时点（不是期间）、全部精确日期、数量少（≤8）、彼此
分得开（同侧相邻卡片放得下）、且有一段间隔明显长于其余。**簇不做**，撞点即退回
编号型。**纵向日期型不做；轴就是一个简单的横轴，最多上下两层。**

**期间型是讲日期时的主力**，四条启用条件：有 spans、≤8 段、至少一段是已发生的事实、
至少两段重叠或包含。**纵向期间型不做**（形态与「标签在条内」冲突）。

**蛇形不做。** 它能解决的容量问题纵向长图全都能解决且更干净；它独有的代价是折返处
阅读方向反转、卡片又分布在轴上下两侧，读者分不清一张卡属于哪一行。

## 5.2 排布

**排布是内部数学，不是用户要选的形态。** 分几层、几列、谁在哪一层、圆点多大，全部
由脚本按几何算。`layout` 枚举里没有「泳道」这种值。用户选的只有图种与纵横。

**A4 的画幅是硬上限，数一律从 `paper.py` 现取**：横版内容 1070×726、竖版内容 700×1096、交付整幅横版 1154×784；8pt 是字号下限。（本节原写「1177px、竖版 722×1092」，那是白边改档之前的数，已过期 —— 凡引用具体像素都要回 `paper.py` 核，不要照抄文档。）

**长图不画任何辅助线**；分页是另一个输出，断点不切卡片、每页重复表头、编号不重排。

## 5.3 视觉

**卡片有 1px `#D6DAE0` 描边，只有深红块无框，块内文字用白色。**

**字号一律取自 `common.FS`**，渲染器里不许写死字号（有守卫）。

**唯一强调色。深红只标已发生的事实**，约定期间画浅色且永不用强调色（有守卫）。

**图上不许出现省略号。** 放不下就让卡片变矮、排布变宽。

**标题区只放图名**，不放页码、日期区间、说明小字（这一条犯过两次）。

**圆点全部实心**，确定度由日期文字本身表达（`2025年2月` 对 `2025.02.12`）加索引
说明，不由圆点样式表达——一排混着实心空心的圆点读起来像一堆台球。

**不确定的事实用虚线框加白底**，连引线一起虚。理由是硬的：浅色区分在白描模式下会被
压成白色、区分整个消失，而**虚线在白描下活得下来**，那正是要提交法院的那一份。

**所有直线走 `geom.hairline`、所有换行走 `geom.wrap_atomic`、所有圆点尺寸取自
`geom.dot_metrics`**（三条都有守卫）。

**正文按法言法语撰写，不许破折号与引号**（书名号除外，有守卫）。

## 5.4 忠实

**verbatim：卡片文字只许删减不许改写**，可检形式是「必须是原句的子序列」。

**逐字核验对规范化后的文本**，不对原始抽取（原始抽取还带着换行和页脚）。

**完备性对账：句子数 = 事件数 + 非事件数**，差一条报错。这是整套召回保证的地基。

**图像来源的事件单独标记**（`source.medium = "image"`），不参与逐字核验、不进离群
检测基准，交付时必须声明哪几份材料没有文字层、有几个事件出自读图。

**材料自身的矛盾要报告，不要自动修正。** 排序遇到「A 依材料应在 B 之后但日期更早」
时报告，让律师判断——自动排顺会把材料的矛盾藏起来。

**冲突有两种**（日期冲突、性质冲突），都必须画出来，任一方都不许删。

## 5.5 脱敏

**脱敏后的可以进仓库，脱敏前的一个字不留。** 脱敏是维护者的工作，不是这个 skill 的
功能。守卫按模式扫不按名单扫。fixture 里不要写形似真实标识的东西。

## 7.1 三泳道：被推翻两次才做对

前文（2.5.7）说泳道不是容量档，那一半是对的。但**三泳道的形状我理解错了两次**：

- 第一次做成「三条横带一路平铺往下」（集团 / 子公司 / 项目公司各一条）—— 错。
- 第二次做成「上二下一固定」—— 也错。

**作者的定义：三泳道是「同一侧可以堆三条横带」。极限是两侧各三条、共六条。**
这与早先定的横轴上限（轴上三个、轴下三个）是同一个数 —— 三泳道不是新东西，
是把那条上限用语义的方式打开。

排法（已实现）：

| 泳道数 | 排法 | 覆盖方式 |
| --- | --- | --- |
| 3 | **默认上二下一** | 下方两条有特殊含义时，在 `lanes` 里写 `"side": "dn"` 改成上一下二 |
| 4 到 6 | 两侧交替铺（上、下、上、下…） | 同上，每条可自己指定 side |
| 一侧超过 3 条 | **拒绝**并说明「请合并泳道或改用纵向」 | — |

**关键的分界（我一直混淆的地方）：** 泳道是**语义分方**（谁的主张 / 哪一层主体 /
哪个程序阶段），层（band）是**几何错开**（同侧排不开就往外加一层）。两者用同一套坐标，
区别只在层号由谁决定：几何触发由 `assign_bands` 按拥挤程度算，语义触发由 `lane` 在
`lanes` 里的次序直接指定（`lane_band` / `lane_side` 覆盖 `band`）。

**没做完的**：上二下一时中间那条侧标压在卡片边上（已量到空档是两层卡片之间）；
三泳道的守卫仍是照错的理解写的，要按上表重写；两个改坏验证漏过。

## 7.2 「按内容划分」彻底舍弃

前文设想过按内容（争点、法律含义）划分材料。**作者定了舍弃，我实测支持这个决定**：

混乱材料里一句话往往同时说几件事 —— 真材料原句「两个月了，验收和付款都没动」同时
落进验收、付款、催告三项，而勾选要求互斥（勾两项不能把同一句画两遍）。
三种判据都试过（法律期间词表、时间成簇、行为词），全部撞在这一点上。

**划分只保留两个维度：材料来源、时间。** 它们天然互斥 —— 一句话只可能出自一份材料，
也只可能落在一个时间点上，判据唯一，所以列出来的表一定对。

**争点不由 AI 认。** 判决书里的争点是法院写好的、照抄而已；起诉状、合同、聊天记录里
没有人归纳争点，且「什么是争议焦点」属于法律判断，超出这个 skill 的边界。
争点由用户在勾选时自己指出。

## 7.3 「先问全部还是局部」是假省 token

前文允许这条路径。**作者指出它是假的**：用户答完，模型照样要读全篇才能划分，
一个字都没少读。

实测（材料一，46 句 1671 字）：划分必须读全篇，这是成本的地板；
而抽取勾一个部分只读 179 到 504 字（全篇的 11% 到 30%），**那才是省的地方**，
而且抽取真正花的是写（每个事项要写文字、算容量、验子序列）。

所以交互只有一轮在前：**读完直接给勾选清单 → 用户勾 → 只对勾中的部分抽取**。

## 7.4 真实材料以杂为主，判决书是少数

**作者纠正了测试材料的代表性：律师用这个 skill 时案子多半还没判。**
更常见的是合同、聊天记录、录音文字稿、零散材料 —— 没有诉称/辩称/查明的结构、
没有人归纳争点、日期写法五花八门。

这一条推翻了「拿判决书调通就算通」的做法。已补一份混乱材料 fixture
（`tests/fixtures/m6-messy.txt`：微信聊天记录 + 录音稿 + 合同摘录混在一份文件里）。

**它当场撞出三个摄入的硬伤，都已修并加守卫：**

- 清页码的规则（清 `-12-`）把 `2023-04-12` 里的 `-04-` 当页码删掉 → 日期变成 `202312`
- 清「3/12」的规则把 `2023/4/12` 削成 `/12`
- **页码夹在日期中间**（「2021 年 6 月 ⏎ 5 ⏎ 22 日签收」）：清掉页码留下两个换行，
  而接回断行只认单个换行，日期永久断成两句

以及切句：聊天记录一行一条、没有句末标点，接回断行那条规则把十五条粘成三句。
现在遇到「下一行是完整的日期 + 时刻」就不粘。**注意这里的判据必须是「完整日期加时刻」**
—— 我先写成「下一行以数字开头」，太宽，把判决书里被排版断开的「6 月 / 22 日」也切开了。

## 7.5 日期型的适用面比想象的窄得多

判据分两半（`check_dated_worthiness`）：几何那一半**问 `feasible.dated`**，
语义那一半（论点落在距离上）留在判据里。

**「任意连续两段之和不少于两年」这条代理判据已删。** 它的推导只在年刻度成立
（D6 要 230px、七格年份每格 115px），而单位是按跨度选的，于是与引擎相反三处、
两个方向都有：短跨度走周刻度时判据过严（把画得出的图判死）、
八点各隔一年时判据过松（每格收到 100.75px、同侧 201.5px 不足 230px，引擎会拒）。

**实测三份真材料，每一份都只有编号型可行**，日期型全部被拒（判决书那份头两个日期只隔
半年多）。所以「列出可行的几种图种让用户选」在真实材料上落空 —— 候选清单里只有一项。

**结论：图种不问用户，后端按几何自动定，理由写进出图说明。** 这回到作者早先定的
「形态选择是自动的，不要再问」。`layout` 字段的归宿是**记录后端定了什么、为什么**，
作为审计记录，而不是让用户选。

## 7.6 死字段是这个项目最隐蔽的一类错

「声明了、校验器管着、渲染器从不读」—— 这一类错看起来像有规则，所以没人会去查。
本轮抓到三个：

- **`time.anchor`**：校验器要求 `certainty=relative` 必须给 anchor，而没有一个渲染器
  读过它。把 anchor 从「2」改成「4」，图上五个圆点位置一模一样 —— 位置实际由列表顺序
  决定。现已由 `geom.order_by_time` 统一排序，并有守卫盯「anchor 改变指向、图上先后
  必须跟着变」。
- **`conflicts`**：校验器一直认它，渲染器一处都不画。现按作者定的画法：冲突的两方
  卡框与引线都用**虚线**（复用「不确定」那条规矩），正文开头加不超 5 字的小括号说明
  是谁陈述（`attrib` 字段，**不能写进 head** —— head 必须是原句的子序列，「原告称」
  三个字不在原句里；但它占同一张卡的地方，算容量时要连括号一起算）。
- **前两轮勾选**：状态里记着勾了哪些材料、哪些时间段，而抽取那一步完全不看。
  现已接上（`pipeline.in_scope`），范围外的事项剔掉并报出来。

**教训写成规矩：新增任何字段时，同一轮里必须让它真的影响产物，并配一个改坏验证。**

## 7.7 交互定为四轮，全程鼠标勾选

| 轮次 | 问什么 | 选项 |
| --- | --- | --- |
| 一 | 制作图表的材料来源 | 每份一行（短名 + 句数 + 日期范围 + 首句）、「全部」 |
| 二 | 时间段 | 粒度**按跨度自适应**（不到两年按季度、两到六年按年、超六年按两年档）、「全部」 |
| 三 | **这张图呈报给谁** | 法官 → 白描；当事人客户 → 奇川风；同行讲课 → 歸藏风；让 AI 定 |
| 四 | 重点标红哪一项 | **只有奇川风有这一轮**（白描单色、歸藏自有规则）；可不选、可让 AI 定、最多一项 |

第二轮跟着第一轮走（勾了哪几份材料，时间列只统计那几份）。
图种不占轮次（见 7.5）。

命令：`read` → `pick` → `span` → `style` → `offer` → `budget` → `capacity` →
`title` → `render`。`pipeline.py steps` 打印全流程，`pipeline.py shape <文件>`
打印那一份 JSON 的形状与判据 —— **这两个命令是给下一个会话用的，别再靠记性。**

## 7.8 期间型：该不该用，不是能不能画

三条判据（`check_span_worthiness`）：那段时间**本身有法律后果**（词表 41 个词：时效、
保证期间、借款与计息、工期顺延停工迟延、租赁期、代持期、举证期限……）、
**起止两个时点都明确**、**至少两段且存在重叠或包含**。

词表第一版漏判过「第二次催告后的沉默期间」—— 那是诉讼时效里最关键的一段，法律意义明确，
只是不带「诉讼时效」四个字。真材料往往描述状态而不写法条名，所以补了沉默、未再主张、
中断、中止、催告、怠于那一组。

**不做「混合型」（编号型加期间条）。** 理由是几何的：编号型的轴是等距的，
而期间条的长度必须等于天数才是真的。在等距轴上画条，条长要么按天数算（轴不是按天铺的）、
要么按跨几格算（那表达的是「跨几个事项」）—— 两种都让条的长度说了材料没说的话。
而「时间轴上既有期间又有时点」期间型本来就支持（`spans` + `points`）。

## 7.9 溯源索引已交付（docx）

五列三线表：图上编号 / 卡片上的文字 / 出自材料 / 定位 / 原文摘录。
中文宋体、西文与数字 Times New Roman、页脚居中页码（9pt，`PAGE` 域不是写死的数字）。
每格纵向居中；编号与定位两列水平居中，其余三列两端对齐；格线比三条主线细
（0.25pt 对 0.75pt）；表格上下的间隔用**段前/段后间距**，不用空段落。

**中西文之间不留空格。** 源文本里的空格要挤掉，且**要在一处统一挤**（逐字段挤漏过
「定位」那一列）。注意：docx 里挤干净之后，用 LibreOffice 转 PDF 看图仍会看到空隙 ——
那是转换器加的，Word 里没有。验过三条路（docx-js 的 autoSpace 属性、styles.xml 默认值、
逐段写死）都无法消掉那个转换假象。

## 7.10 反复出现的方法论错误（**这一节比技术细节值钱**）

- **判据要让被测的规则成为唯一的原因。** 改坏验证漏过多次，原因都是样本里同时触发了
  别的判据，或者判据拿数量比对而改坏后数字恰好仍满足。
- **守卫拿不到材料时不能静默跳过。** 交互两轮的守卫指向仓库外的路径，目录不存在，
  整段被 `if` 跳过 —— 三个改坏验证全漏，而我以为是判据写得不好。**测试材料必须在仓库内。**
- **凡「每处都要记得做一次」的事，收成一个出口统一做。** 中西文挤空格、引号转弯、
  坐标吸附，都是靠记性就会漏。
- **同一个东西的第二种算法要复用第一种，不要重写。** 叙述块的段号换句号时我自己抄了
  一遍折叠规则，抄偏一句。
- **比对两个数之前，先确认两边数的是同一种东西。** 时间段守卫拿去重后的 11 去比
  出现次数 17，误报成 bug。
- **有明确信号时不要猜。** docx 里标题是 Heading 样式，我先按「短且不带句末标点」猜，
  猜不对。
- **指出问题与修掉问题是两件事。** 期间型容量那处，我发现「拿最短段套全图」是错的，
  却只改了提示文字没改检查本身。
- **视觉决定不许自己拍。** 我曾自己发明冲突记号（圆点旁带圈的「甲」），被作者否掉 ——
  那个记号只有我懂，还与当事人代称撞名。**图上要出现什么，问作者。**
