## 4. Build & Packaging Slimming Audit (`scripts/build-libreoffice.sh`)

ElyOffice's `scripts/build-libreoffice.sh` contains three high-impact build and packaging optimizations that we have audited for `desktop/lowa-build`:

1. **Bundled Spellcheck Dictionary Pruning (`PERF-01`)**:
   - **Discovery**: Bundling all ~65 LibreOffice `dict-*` extensions adds ~473 MB uncompressed and increases LOK cold start from **1.1s to 5.4s** (warm start from 0.7s to 2.3s) because Linguistic enumerates and registers every dictionary extension on startup.
   - **Porting to AI WorkDeck**:
     - Our target UI and document locales are Simplified Chinese (`zh-CN`, which does not use Hunspell spellcheck dictionaries) and English (`en-US`).
     - In `desktop/lowa-build/patches/apply-source-patches.py`, `--slim-dictionaries` (and `slim_dictionaries()`) prunes non-essential `dict-*` directories from `instdir/share/extensions` (keeping `dict-en` and any `dict-zh*` if present).
     - In `desktop/lowa-build/patches/fs-image-patch.py`, we both filter `static/CustomTarget_emscripten_fs_image.mk` and provide direct binary+metadata slimming (`slim_fs_image_package()`) on `soffice.data` + `soffice.data.js.metadata`, stripping non-`en`/`zh` `share/extensions/dict-*` entries and recalculating contiguous `[start, end)` byte offsets and `remote_package_size`.

2. **`Lightproof.py` & Python Grammar Checker Stripping**:
   - **Discovery**: `dict-en` ships `Lightproof.py`, `Lightproof.components`, `Linguistic.xcu`, `pythonpath/`, and `dialog/`. In builds with `--disable-python` (both LOWA WASM and headless LOK), `Lightproof` is completely inert yet adds file-table/MEMFS overhead and causes component registration hangs on Windows.
   - **Porting to AI WorkDeck**:
