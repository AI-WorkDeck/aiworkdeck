# 原生文档引擎与轻量数据层样板：2026-10-24

结论：样板已跑通，显示出显著提速潜力；尚不满足「快很多且不影响其他体验」的默认实现合并条件。保留实验分支，不替换产品入口，不发版，不移除 Windows。调查状态：DONE_WITH_CONCERNS。

本轮窗口仍使用 Electron。Swift 仅承担隔离 SQLite 数据服务，文档引擎是原生 LibreOfficeKit。结果不能用来证明必须重写整个 Swift 界面。

## 实际实现

- [local-data](local-data/README.md)：真实项目/文件元数据、字节读写、设置、单一所有者、generation 冲突检查、保存日志与两处进程崩溃恢复。没有连接用户 H2 数据。
- [native-lok](native-lok/README.md)：真实文档模型、原生瓦片绘制、输入/导出与可选深层 UNO 探针。运行时来源与许可见 [UPSTREAM](native-lok/UPSTREAM.md)。
- [workbench](workbench/README.md)：可见实验窗口，把前两者连接起来；显示真实 SQLite 文件、绘制真实文档像素、接受独立文本框中的中文并通过原生导出和受保护保存写回。

产品原有 Java、前端、默认编辑器入口、打包和发布流程均未改动。第三方应用、运行时二进制、测试数据库、合成文件与原始日志不入库。

## 测量结果与限制

固定产品基线 `8d9eddde694b521dc1abfde943a56ab2565f7698`。输入是同一份 60 段、600 处修订 DOCX，SHA-256 `42d60dcc51b4329be843e38c96c305c1aea676eba678f01742fb46d28c84b50e`。每组按 B1/A1/A2/B2/B3/A3 交替运行，新进程、新 HOME、独立数据库/引擎配置；任务内不并行构建或测试。两侧 UI 均预置一个项目和同一文件，窗口内容区 1280×900，实际设备像素密度 2；原生瓦片为 1600×1800，运行时从 SSD 解压目录加载。OS 文件缓存未清空。

**机器当时的系统负载读数异常高，时延明显波动。以下是这次环境中的观察，不是正常使用预测，不能与上一轮约 6.5 秒直接换算。** 此外，样板缺少大量完整产品能力，字体栈、页面缩放和编辑交互并非完全相同；窗口和数据层数字尤其不能当作同功能替换的提速百分比。

首次从压缩 DMG 读取、低于实际像素密度的试跑，以及意外触发浏览器下载的 Java 夹具试跑均保留在工件中，未计入上述统计。

## 已验证内容

数据层 30 项真实进程/SQLite/文件测试通过，主任务独立复跑通过。覆盖重启后 ID/UID、实际 DOCX、两次旧 generation 写入、外部修改/删除、跨项目地址、软/硬链接、只读失败、唯一所有者、损坏数据库和两处强制进程退出恢复。独立审阅发现的 NUL 设置键别名覆盖先在旧二进制复现两项失败，再修复为全部通过。未声称断电和所有创建事务恢复已覆盖。

原生引擎能够输出真正的中文正文和修订标记。600 处原始修订的类型、作者、日期、文字及顺序保留；原生键输入/中文粘贴、精确 URL 绑定 UNO 模型、核对锚点后替换、撤销/重做、最终稿读取及导出通过。原始稿/最终稿按文本语义验证，未把 XML 节点拆分当成丢修订。

三轮最终整合均通过真实截图、HTML composition→原生 paste→DOCX 导出→SQLite generation 保存，退出码为 0。独立回读磁盘与 SQLite 的大小和 SHA-256 一致，pending 日志清空，600 组原修订语义保持。整合输入文件未开启记录新修订，新增输入作为普通文本保存；移除唯一新增标记后原始稿投影保持不变。该场景与引擎探针显式开启跟踪后的原始稿不变断言分别验证。

这些检查不等于 macOS 系统输入法候选窗或真实文档光标操作验收，也不等于全部现有编辑器断言通过。

## 合并阻断项

1. 这套原生运行时没有产品使用的 `AwdReviewGeometry` 和 `AwdReviewSidebarWidth`；审阅侧栏、气泡定位等定制补丁需要迁移验证。
2. 原生文档的光标、键盘/鼠标、系统输入法候选位置、富剪贴板、多文档状态、复杂版式与完整工具栏尚未接入。独立文本框粘贴不能代替这些体验。
3. SQLite 尚未迁移 H2 项目/文件身份、权限、文件监听、Git 版本、AI 写入、保存/还原协议和外部目录。不能让 Java 与 SQLite 同时拥有写权限。
4. 仅部分 UNO 原语通过；完整 AI 命令、锚点/文件身份、超时/取消/迟到结果与恢复协议仍待迁移。
5. 需在正常负载下，保留同等产品能力后重跑启动和可编辑首屏，而非把极简样板时间作为产品承诺。

建议后续先明确数据所有权和迁移/回滚，再迁移原生文档宿主与审阅补丁，最后按完整体验验收。当前证据支持继续这条架构路线，尚不支持直接切换默认实现或全盘重写 Swift 界面。
