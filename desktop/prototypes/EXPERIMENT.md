# 原生文档与旧项目接续样板：2026-10-25

本轮已完成原生崩溃的同源负对照、隔离 H2 快照到 SQLite/文件树的迁移和真实编辑回读。**产品默认入口仍等待 Java；完整数据写权迁移和体验等价门槛尚未通过。** 保留 Draft PR，不合并默认实现，不发版，不移除 Windows。

窗口仍使用 Electron，文档模型和绘制使用原生 LibreOfficeKit。Swift/SQLite 独立模式可读取迁移副本并持久保存，不启动 Java；兼容模式的 H2、文件和 Git 写入仍由 Java 负责。两种模式的功能覆盖不同，不能混合报告启动成绩。

## 2026-10-25 继续修复的实测结果

- **原生生命周期崩溃**：按相同源版本、53 个上游补丁和自有审阅几何补丁构建。仅反转 `SwXRedline::release()` 的 SolarMutex 修复，600 条临时 UNO 修订读取第一轮即 SIGSEGV；冻结的修复版两次分别连续 20 轮通过，文字/身份 hash 相同，UNO 与 worker 正常退出。负对照栈再次落在 `SvtBroadcaster::Broadcast` → `SwXRedlines::getByIndex`。这证明本次竞态的修复，不保证所有原生挂起均已消失。构建、补丁和许可见 `native-lok/UPSTREAM.md`。
- **审阅几何与保存**：controller 已实际返回 600 处几何，包括第 599 项和非零纸边宽度。原生探针在气泡显示下导出，以及两次裁决后连续 undo/redo，独立回读均保留全部原修订和 all/original/final 文本。UI 仍未实现完整气泡、批注和关联组操作。
- **审阅与输入调度**：摘要先显示，完整文字每批最多 25 条；每批结束释放原生队列并让出界面事件循环。未取到完整文字的卡片不可操作；批次前后验证文档/修订身份，点击时再验证完整目标。实际窗口已通过正文出现后立即输入、保存、两次裁决的键盘撤销/重做、中文确认/取消，保存后的 600 组修订与三个文本投影保持一致。
- **默认修订跟踪差异修复**：第一组新正常负载回读发现，正式编辑器的新输入会生成第 601 组修订，而样板把新输入作为普通文字；因此该组速度不能作为体验等价通过。现在按产品语义在交付可编辑模型前开启并读回 RecordChanges，增加独立开关与输入后的防抖审阅刷新。真实窗口已核验默认开启、关闭、再次开启及显示切换；DOCX 的原始/最终文本、跟踪开关和新增修订语义分别吻合，600 组原修订保持不变。新增 Node/Python 全集主任务复跑 100/49 项通过。修复后的速度另行测量。
- **隔离迁移**：只读真实 H2 导出全部 97 表的行与结构、源 hash 和 identity 高水位，再将明确选定的项目文件复制进独立 Swift profile。保留项目/文件数字 ID、UID、目录父子关系；未转为可用业务表的数据逐行存档。真实副本重开后读取/保存通过，源 H2、源文件 hash 不变。存档不等于 ACL、AI、版本和云同步已经迁移。
- **生产启动回调**：此轮另有 `LocalRootWatchService` 与提交后删除通知的最小后端改动，将全项目目录注册移出同步启动回调。它不等于将 JPA/H2 从完整产品启动链移除；相应并发、事件补偿与事务边界单独验证。

这一轮机器多次出现很高的后台负载，`functional-ui-*` 与 `phase-investigation-*` 仅作为功能/诊断记录，不计入正常负载收益。新增分段记录发现，新编译运行时首次 profile 的扩展注册占据约 5 秒；采样主线程在 `SynchronizeExtensionRepositories`。不能将旧 Ely 运行时的较快成绩归给新构建，也不能靠提前发 ready 掩盖这一段。 已核对这是遗漏现有打包步骤引入的 65 套字典扫描；新候选复用仓库已有中英文资源筛选，保留的 33 项英语资源与旧 Ely 逐文件相同，全部差异限制在扩展目录，未改引擎/字体。正式性能数字仍须另测。

最新本机证据目录 `2026-10-25-startup-data-migration`：`native-lifetime-comparison.json`、`native-lifetime-control-builds.json`、`port-verify-v2.json`、`review-patched-1/`、`migration-word-clone-2-readback.json`、`ui-root-saved-verification.json`、`runs/functional-ui-3-batched/`、`engine-start-sample.txt`。二进制、数据库、合成文档、截图和原始日志不入库。

## 前轮已接通的兼容模式范围

- **正文输入**：透明输入控件跟随原生光标，鼠标和键盘映射到文档坐标；确认后的中文通过原生扩展输入提交，预编辑取消不写入正文。输入序号、文档代次和回执防止重复、迟到输入写进新模型。切换、恢复和退出先排空输入并保存；纯文本复制/剪切读取真实选区，空选区或剪贴板失败不会删除正文。
- **审阅侧栏**：读取真实作者、类型、完整修订文字与坐标；使用原生修订 ID 和当前快照定位、接受/拒绝。定位后核验 URL 绑定模型的实际光标范围；操作后重新核对目标层和其他已有条目。支持显示修订/最终稿两态，未知操作结果锁住当前通道。CAPI 和多步 UNO 操作在宿主中串行处理。
- **版本历史**：读取原后端的 Git 时间线、保存版本、恢复版本。恢复先关闭旧原生模型，再调用原后端恢复、重新下载并打开文件；新的操作回执到达后才报告成功。实测包含恢复后再次保存，防止旧模型把恢复结果覆盖掉。
- **旧项目接续**：兼容适配器检查后端构建、本地身份、存储根，保留项目/文件 ID、UID、路径和原 Git 库。SQLite 仅保存上次观察到的目录和未决操作保护；清除目录缓存不会清掉未知写入记录。

**旧项目接续不是 H2→SQLite 的完整迁移。** SQLite 目录不是事务快照；权威字节、保存和版本操作仍等待 Java。上传前 hash 校验不是服务器端 CAS，不能消除另一客户端同时写入的窗口。AI checkpoint、多窗口、文件监听和云端写入协议仍未迁移，不能给 Java 和 Swift 同时发放实际文件写权。

前轮改动限定在 `desktop/prototypes/`；本轮新增上述后台监听改动。正式桌面入口、打包和发布流程未切换为原生/Swift 实现。第三方运行时、合成文档、数据库、截图和原始日志均留任务工件，不入库。

## 前轮验证与失败记录

主任务实际执行：输入组件 **23/23** 测试、兼容层 **14/14** 测试通过。输入测试覆盖 composition 顺序、取消、重复回声、旧文档回执、坐标、冻结、保存、剪切失败；兼容测试采用 mock HTTP 与真实 SQLite，不能替代真实后端验收。另在独立 Java 21/H2/Git 上执行真实 API 测试，原 ID/UID、磁盘文件、版本恢复和清缓存后读取通过。前轮 Swift 数据服务 30 项测试为既有证据，本轮未改其实现。

原生探针实际覆盖 600 修订、原生 ID 接受/拒绝、过期快照、输入序号、关闭重开后的旧代次拒绝、中文导出回读；可选 UNO 回归包含同一插入/删除在 all/final/all 下重复定位，读取实际光标起止范围。相邻不同作者删除和叠加修订小夹具通过；拒绝上层删除后原插入层保留。表格 A1 内中文与 emoji 输入导出后只在目标单元格出现一次。

完整窗口 `ui-java-final-3` 已通过实际审阅、撤销、输入、版本创建、恢复、再次保存和正常退出。保存文件另由主任务读 ZIP/XML 核对：600 组原修订的类型、作者、日期、文字相同；第一版新增中文只出现一次，第二版与取消预编辑的文字均不存在；去掉唯一普通输入标记后 all/original/final 文本投影与原文件相同。XML 节点拆分不等于丢失修订。

本轮修复的实际问题包括：CAPI JSON 修订参数应使用 `uint32` 而非 UNO 的 `unsigned long`；显示枚举写 0 会被归一为 1，应读 `ShowChanges` 验证；删除修订选区的复制文本可以为空；重复获取临时 UNO 修订对象曾导致 SIGSEGV，改为单次获取并持有后回归通过。该轮当时未证明生命周期根因；本轮后续同源负对照见上节，仍不能宣称所有原生崩溃问题已解决。失败试跑、崩溃摘要与成功复跑均保留，未计入有效性能统计。

早期自动输入未能核验 macOS 候选窗，不能用 CDP composition 或原生中文提交代替系统验收。随后用户在隔离窗口用真实键盘切换已有中文输入法，确认“中文验收”并输入拼音后按 Esc 取消，明确回复“正常，且已切回原输入法”。主任务再通过真实界面保存并独立回读 DOCX：“中文验收”出现一次，去掉它与既有普通输入标记后，all/original/final 三个投影与原夹具一致，没有额外取消文本；600 组原作者/类型/日期/修订文字保持一致，窗口正常退出 0。这是用户对候选窗的实机观察加主任务的保存回读，尚未覆盖其他输入源、跨表格候选、候选期间切换文档等组合。

## 合并门槛尚未通过

1. 接回原数据权威后，完整启动仍约 6 秒，未达到用户要求的明显改善。保留后端初始化依赖的缓存目录不是轻量数据层迁移完成。
2. 原 Ely 运行时缺 controller 几何属性；本轮自建引擎已补齐并实际验证。完整三态气泡/批注 UI、关联修订分组处理仍未迁移。
3. 单窗口系统输入法确认与取消已通过上述人工/回读验收；富剪贴板、完整工具栏、多文档/分屏、复杂版式和完整 AI 命令/锚点/迟到结果协议仍未通过等价验收。
4. 旧项目完整迁移、跨客户端同时保存、watcher/云同步、AI checkpoint 恢复尚未完成。已测的普通 Git 版本恢复不能覆盖这些协议。

当前证据支持继续原生文档路线，也表明数据权威必须真正拆出启动关键路径；尚不支持将这个样板切为默认编辑器或以 Swift 重写来承诺整机启动速度。
