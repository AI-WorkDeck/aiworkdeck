# 项目沟通

纯 Web IM 插件。0.2.0 的沟通助手需要包含 `agentScopes`、`ensureAgent`、`agentReply` 的 AI WorkDeck 0.69.0 或更新宿主及相应协作服务；仅更新插件无法增加旧服务端的能力。当前使用中国大陆站 AI WorkDeck 账号，连接 `case.aiworkdeck.com` 官方协作服务；国际站账号暂不支持。源码、宿主和云服务分别发布，实际可用状态以插件广场及正式版本为准。

## 助手与会话

层级为律所、团队、项目；没有额外的“组织”层级。打开项目沟通时默认建立或打开本项目的共享助手群，助手明确标记为 AI，不注册成真人、不增加真人成员数。现有群的非成员必须通过邀请码加入，知道项目标识不等于获得历史访问权。加入团队、律所后，可打开各自的共享助手会话；其资格由服务端实时核验，退出相应团队或律所后不能继续读取旧群。通讯录收在辅助入口，主区直接展示对话。

工作台侧栏已经显示会话列表时，插件只显示聊天；收起工作台侧栏或单独打开插件时，恢复插件自己的会话列表。聊天内的“通讯录”按钮展开当前可用侧栏中的通讯录，不重复展示两套导航。

仅有一位真人的助手群以及助手私聊，发送消息后会请求回答；多人群通过“请助手回复”明确唤起。助手只读讨论，不修改项目文件。共享回答使用本群最近讨论，以及明确向全群开放的最近附件（最多4件、每件正文最多6000字，不自动启动OCR）。团队、律所助手另外读取所选层级的共享记忆索引，不读取其下所有项目。未读取和截断的资料在模型上下文中明确标记，助手不能据文件名猜正文。

“私聊助手”建立仅当前用户可见的独立会话。项目私聊由宿主验证当前项目归属后补入该用户可读的档案、项目记忆索引、最多40个文件名与最多4份材料正文；不会加入个人记忆或其他项目。客户私聊不读取律师内部档案或项目记忆，文件仍按原访问权限过滤。私聊内容不自动发进群。沟通助手使用官方云端模型和提问者的平台 AI 额度，不使用桌面端选择的本地模型或自备密钥；缺少可用额度时明确失败，不借用服务器密钥。输入区说明资料范围与云端处理。排队、运行、失败状态可见；重试沿用原消息标识，已完成请求不会重复生成。

项目标识复用 Git 中的 `项目沟通/项目标识.json`，克隆或换设备后仍指向同一项目助手。首次由有写权限的内部成员创建；尚未创建标识的只读成员仍可打开其团队、律所助手。项目访问权限与会话成员资格独立：撤销本地项目权限阻止新的资料提取，但不会收回已经提交到云端的本轮资料快照或删除既有聊天；团队、律所会话则每次核验相应层级的成员身份。

## 与成员沟通

在插件工作区创建群聊或两人私聊，负责人生成带角色的邀请码，其他用户凭码加入。邀请码持有人能读取历史消息；文件另按访问权限开放。邀请码应只交给预期成员。角色分为负责人、成员、客户。消息使用当前登录账号身份，跨团队/律所的沟通以会话成员资格授权。

本机文件限 8 MiB；可选择项目文件，发送带项目与文件唯一标识的受控版本快照（源文件后续更改不自动替换）。文件默认内部可读，客户需由上传的律师或负责人单独开放；客户本人上传可自行读取。无权文件只显示待准备占位，无法预览、导入或交给 AI。撤回开放只阻止后续读取，已经保存的本地副本无法收回。可读附件可直接「下载」，不要求项目写权限，也不会写入项目目录。下载由宿主保存对话框或浏览器下载列表处理；取消保存不表示已完成。收到的文件点击「存入项目」后，能在中间标签打开、添加到 AI 或拖入 AI 对话。拖拽仅传递宿主校验的短期文件引用；不会把原始文件内容塞入提示词。插件不会自动下载全部附件。

「关联当前项目」创建带项目唯一标识的关联记录；首次引用时，具有项目写权限的内部成员会自动创建该标识，其他成员须等待项目完成关联。「归档聊天」将当前会话存入项目，供用户纳入 Git/版本记录（每次最多10000条且16 MiB，超限不会保存不完整记录）。远端聊天和项目归档是不同的存储，不会自动将整个聊天数据库提交到 Git。

消息每 3 秒增量拉取；发送失败保留待发送内容，重试沿用消息幂等标识。草稿仅在插件内存保存，关闭插件、切换项目或账户会清除。客户端不存消息到 localStorage。此版本不含语音/视频通话、已读回执展示、撤回、微信互通或端到端加密。

## 构建与验证

执行 `./official-plugins/project-im/build.sh`。测试复用前端安装的 jsdom（先按仓库指引安装 frontend 依赖），输出 `dist/project-im-0.2.0.zip`。构建从仓库 `sdk/plugin-sdk/awd-plugin-sdk.js` 直接放入 ZIP，避免维护过期 SDK 副本。

测试覆盖合成 DOM 流程与安全边界；跨账号真实联网、正式安装/启用/工作区及客户端发版须由集成验收单独确认。

后端数据库以云端 PostgreSQL / 桌面 H2 PostgreSQL 模式为目标，附件 bytea 映射不支持旧 MySQL profile。客户端升级、云服务部署、插件签名上架是独立发布步骤，必须一起验收；本包不能单独给旧宿主使用。
