# 国家范围与法律引用

## 确定国家
先从已提供材料提取销售/部署国、被服务或监测人群所在国、控制者和处理者营业地、实际决策地、采集/存储/访问/接收国。分别记录：候选国家、已明确纳入国家、排除国家及理由。国家被纳入调查范围不等于该国全部法律已被证明适用；实体法律仍须逐项判断地域、主体和事项适用。

“欧洲”不等于欧盟，更不等于已覆盖所有成员国；英国、瑞士等不能自动套GDPR包。语言列表不能推导销售国家。数据存于中国不自动排除欧洲法律，也不单独证明某一出境法律机制适用。不得仅以总部或云区确定主监管机构。

`meta.countries`记录每国 code（两位国家代码，不用EU）、name、status（confirmed/candidate/excluded）、connection（角色与地域连接分析）、source_ids（材料或用户答复）、authorities（机构名称及主管权待确认状态）、law_review（pending/verified/not_applicable）、law_analysis（适用及差异）、law_refs（source_id+locator）。`confirmed`表示范围已有证据，不表示所有法条适用。一个国家有多个连接角色时放在connection中解释，不重复造记录。更新国家/法源会触发复评。

首轮确实缺信息时，优先询问：“产品实际在哪些国家上线或试点？哪些实体决定数据用途和处理方式？”已提供的信息不重复问。国家未答时补问并保留当地覆盖未知；独立成立的GDPR共通触发可明确有限范围判断，不能宣称当地清单已查全。用户要求先出报告时仅按outputs给范围受限、缺失留空的草稿。主体问题以实际业务事实提问，不要求用户自行完成法律角色认定。

## 各国检索与分析
按实际国家检索官方现行文本，并记录本次核验日期、版本/生效状态、精确条款、适用连接与例外：
- 欧盟成员国：GDPR共通义务；该国补充数据保护法律；当地Art35(4)/(5)清单及适用主管机构；与终端设备、雇员、未成年人、健康或行业有关的实际国内规则。仅遇相关事项才展开，不能把所有特别法机械列为适用。
- 非GDPR法域：本版不展开，说明边界；境外接收只评GDPR义务及专项衔接，不自动激活其他法域包。

官方入口示例（仅检索入口，不是预核验的全国规则包）：法国Legifrance与CNIL；德国Gesetze im Internet、DSK及相关联邦/州监管机构；其他成员国通过EDPB成员机构目录查当地官网。不要为了凑“本国法律”引不相关法条；未找到相关差异，应写明查阅范围及为何共通法条足以支持该项判断。

## 可阅读的法律引用
每个重要判断写成“材料事实及定位 → 法律名称和条/款 → 本案适用理由 → 结论/限制 → 处理建议”。例如材料仅规定无限期保存时，论证保存目的与期限的关系，引用实际核验的保存限制条款，不直接把一个内部风险编号作为理由。

正文就近引用“GDPR第5条第1款(e)项”，并加官方链接/脚注；国内法使用原文正式名称，中文译名标注工作译名。法源目录列官方URL、具体条款、效力（法律/条例/指南/草案/内部方法）、版本、本次核验日期、适用国家和对应问题。不能只列一串法律名称，也不能用监管模板替代法律。

项目新增官方法源登记为sources（kind=other，locator填已读取的具体条款，version/observed_at完整），引用在law_refs和具体rule_assessments.source_refs中使用；国家特有独立义务在law_analysis逐项论证，需规则引擎筛查时依extension扩包。核验未完成必须pending，工具只检查引用存在，不验证法律正确性。
