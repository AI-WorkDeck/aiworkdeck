# GDPR流程与EDPB指南映射

## 方法依据

本版采用EDPB认可的WP248 rev.01（2017-10-04修订），不是自行创设法律推理方法。2026-09-14核对[EDPB认可页面](https://www.edpb.europa.eu/documents/guideline/data-protection-impact-assessments-high-risk-processing_en)及[指南原文（CNIL官方副本）](https://www.cnil.fr/sites/default/files/atoms/files/20171013_wp248_rev01_enpdf_4.pdf)。各次运行仍核查更新，EDPB模板不替代指南。

| 实质任务 | 必读定位（原文印刷页） |
| --- | --- |
| 界定单一/相似处理范围 | III.A，第7页 |
| 必要性筛查及例外 | III.B，第8—13页 |
| 既有处理变化及持续更新 | III.C、III.D(a)，第13—14页 |
| 参与者职责及意见 | III.D(b)，第14—15页 |
| 实施DPIA的方法和共同标准 | III.D(c)，第15—17页；附件2，第22页 |
| 公开与事前咨询 | III.D(d)、III.E，第18—19页 |

按上述原文及GDPR35(7)覆盖处理说明、必要性/比例性、个人权益风险、应对措施及参与程序。保留各项对应法条和理由，不用模板填满、指标数量或工程校验替代。GUIDE中的可选方法不等于EDPB统一强制评分模型。本文件以下规定交互和记录，不改变指南实质要求。

## 1 事实确认

先识别是否已有assessment_id。按目的拆活动，记录收集、传输、使用/推导、存储、访问分享、保留删除、备份恢复及权利退出。首轮只补足筛查事实，完整评估细节在需要DPIA后展开。未知不是否，尚未设计可以是已确认事实，不因未实施就拒绝设计阶段评估。

## 2 筛查关口

模型先依据原始材料填写法律适用、触发及排除理由，screen仅汇总：
- required：已有完整强制触发且法律适用，进入内部评估；其余未知保留。
- no_trigger_identified_within_assessed_scope：只有相关条件已逐项排除、当地清单覆盖核验、范围无关键未知时才结束本轮；保留理由及复评条件，不等于整体合规通过。
- outside_scope：有依据认定GDPR不适用，结束本版范围，不自动转其他法域。
- undetermined/applicability_unresolved：继续集中补问影响筛查的事项。
- recommended_high_risk_review、exception或conflict：提示尚需法律判断，不自动当作required或豁免。

WP248指标不是机械法定计数。没有完整国家范围时不能宣称当地清单已覆盖；若共通强制触发已独立成立，可以作有限范围的需要判断。用户提前要求文件而筛查未定时，仅生成明确未完成筛查的结构草稿，不虚构完整风险结论。

## 3 内部评估

按指南定位开展实质分析；默认简洁摘要和风险/整改清单。每项必须有具体法律、事实到个人损害的分析、风险级别与理由、措施和建议/验收；详细底稿按需展开。缺事实只暂停依赖它的判断，已知缺陷进入整改。GDPR范围外专项仅说明衔接，不声称已完成。

暂停前执行source-trace.md的实质性阻碍分类及范围记录：问询等待不等于整体评估停止，未知也不必然禁止条件分析。WP248 III.D(a)第14页要求尽早在设计阶段开始，即使部分操作尚未明确，之后持续更新（2026-09-15复核官方原文）。有依据的已知缺陷可以先评估；缺关键事实时允许暂缓其风险等级或具体结论，不强迫给出确定等级。

## 4 用户选择报告

整改后补材料：记录变更和证据，重评受影响风险，再出报告。现在要报告：保持draft，未知答案留空并原生批注，依赖结论未定；已知缺陷保留正文。两者均不生成虚构人类批准。详见outputs.md。

完整评估完成、报告草稿生成和批准上线是三个不同关口。未答问题不禁止向用户提供上述选择；用户要求草稿不解除事实或程序缺口。整个评估对象不明时，仅可给明确标识限制的结构草稿，不能包装成完成评估。

## 5 同一评估与更新

优先按assessment_id匹配；没有ID时按项目、责任主体/待定责任范围、目的、处理活动及国家检索候选，不能只凭名称或同一PRD合并。无法唯一识别则请用户确认。主体尚未选定不阻止建档。

原问题补充、同范围设计整改及实现进展通常沿用ID并新增revision_id。主体、目的、国家、技术或处理范围重大变化先判断原评估是否仍能覆盖；新独立业务新建ID并以related_assessment_id关联，不静默扩张原范围。分组相似性按III.A核对，而非ID相同即证明可合并。

保存旧版，再比较事实、控制、法源、模板和范围，沿依赖链重开受影响结论。新增信息有冲突时保留双方，不自动采用最新文本。未变化且仍有效的证据可复用，旧批准不覆盖新版本。报告绑定当时revision_id、模板及法源版本。风险改变触发复核，不需要DPIA的旧结论也可重新打开。
