# 正式报告交付核对

适用于原模板、自建GDPR结构、完整内容稿及提前草稿。实质方法仍是WP248及risk-method.md；下列是产品交付约束，不是EDPB额外程序。不要为通过检查修改原试验产物或补造用户事实。

## 内容先于文档转换

- 使用同一assessment_id和当前revision_id，确认未决依赖。实质纠错先回写事实/规则/风险/措施及来源，再生成新版本；不得只修Word而使底稿保留旧判断。
- 按report-basis.md核对全部相关维度，建立维度→正文位置/具体未决栏位映射。草稿可部分分析或明确未开展原因，不可静默删掉特殊类别、行为准则、逐目的基础等问题。
- 风险段保留legal_refs中每一具体条款/指南定位和来源名称；可用就近脚注或链接。法律分析、个人损害、概率/严重性理由、等级、现有控制及进一步措施效果限制和整改关联必须一致。文末资料总表不替代逐风险法源。转换前执行source-trace.md“事实传递核对”，以已经纠正的底稿生成正文，不在Word生成脚本中重新概括实质判断。
- risk-method.md的评级边界适用于所有输出。拟议保护须纳入分析；原文已明确的降频、关闭、人工复核及其适用时点不能在结论中消失。上线建议与法律义务、措施有效性分别说明。
- 未知字段答案保持空白，批注锚定该字段标签或空回答段；同一未知事实在不同实际填答位置重复出现时，每处均须可就近找到补充提示。集中问题包只作索引，不能替代正文缺失字段的批注。业务补问共用source_trace.question_packets返回的comment（已有材料、差额问题、影响、建议），不再次拼入原始宽泛问句。此前未发现的缺口先回写checks和questions；责任人等报告阶段新字段也按相同差额原则处理。已确认尚未设计应如实填写并评估。

## 面向读者的Word结构

自建结构按“范围与生命周期/权利事实—DPIA筛查—必要性与比例性等评估—风险与整改—意见程序及复评”组织；用户指定的适用原模板则保留原栏目，通过映射补齐内容，不擅自换成自建结构规避勾选。模板选择已知且有判断依据时按原选择语义填写，未知保持未选并就近批注。

- 标题、指标和评估维度使用可读名称，不只放EU-I/EU-C等内部代码。报告版本与输入PRD版本可列在版本信息区，测试轮次不能占据业务版本；assessment_id等追溯信息放版本区或技术附件，不当作业务答案。
- 法律短引就近保留，事实来源用原件标题与章节/段落的简注或脚注；完整事实ID、哈希与反复出现的来源编码移到追溯附录。不能为了精简删除法律定位或事实条件。
- 风险论证用短段落配紧凑等级/措施表，避免短标签占半页宽的等宽长表。整改集中列出、风险处引用编号，结论概括关键决策，不再次复制全部整改和机器维度清单。
- 只对主要章节设置必要分页，风险小节自然续排，标题与首段同页；逐页检查表格续页、孤立尾行、异常留白和中西文字体一致性。页数不是质量指标，不靠压小字号或删除分析缩页。最终审核依据最新DOCX对应渲染，不把中间版本已修复缺陷列为最终问题。

交付时分别说明内容核对、机械映射和版面检查的实际覆盖。自建结构通过不证明原模板适配通过，未实际运行的勾选/模板路径标为未验证；不据此增加另一轮独立测试。

## 可核验的Word对应关系

生成器应直接使用当前记录，保留每个风险引用的source_id与locator；三类等级分别映射为高、非高、未定，不能把所有非high值都写成待定。生成后用`scripts/check_report_docx.py`只读核对成品，避免底稿有法条而Word丢失。

```text
python3 <skill>/scripts/check_report_docx.py assessment.json report.docx bindings.json
```

bindings是技术附件，不是业务报告。由实际成品XML位置建立，索引为`word/document.xml`中全部`w:p`的零起始序号（含表格），不是页码。可用现有`fill_official_docx.py inspect`查看段落；不要猜索引。脚本校验：

- assessment和DOCX的SHA256、assessment_id/revision_id一致；风险集无遗漏/重复，按所绑定的独立风险范围检查该风险每个原始locator和来源标题、其等级专用段；本地脚注/尾注中的引用也可检查。
- 未知答案段为空，批注真实存在且锚定同一字段所在表格行或相邻标签/回答段；批注包含经核对的具体问题、影响和建议文本。不把文末Q答复栏冒充正文中的控制者栏。

bindings结构示例（所有数值、文本及hash必须来自实际成品，不照抄）：

```json
{
  "assessment_id":"实际ID", "revision_id":"实际修订ID",
  "assessment_sha256":"实际文件SHA256", "docx_sha256":"实际文件SHA256",
  "risks":[{"id":"R1", "start":20, "end":35, "rating_paragraph":22}],
  "unknown_fields":[{
    "id":"controller", "label_paragraph":4, "answer_paragraphs":[5],
    "comment_id":"0", "question":"具体待补充内容", "impact":"具体判断影响", "recommendation":"建议材料"
  }]
}
```

start/end均含端点；范围只覆盖该风险及其就近引文，不能把全篇或公共法源附录绑定给每个风险。评级段只放等级文字（高/非高/未定，未定兼容待定），字段标签放同表其他单元格。原始locator可原样置于中文法源名称后，以保留可核对性；需要译写定位时另做人工原文映射，不悄悄降低检查。所有未知字段必须列入unknown_fields；没有未知则为空数组并经内容审查确认。

这是传递与锚点检查，不会自动识别遗漏的业务字段、评估维度或被忽略的事实，不证明法源有效性、评级合理性或批注充分。特殊模板无法建立此映射时明确记录不支持的项，并逐项人工核对，不宣称脚本通过。按Documents要求另验选择语义、批注关系和逐页渲染；中文macOS使用codex-render-docx。只有最新成品与内容、结构、视觉三个证据相符，才能报告对应范围通过。
