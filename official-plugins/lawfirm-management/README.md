# 律所管理

官方律所全业务管理 Web 插件，0.1.12 需要具备云端利冲协作、消息中心 API 及计时收费接口的宿主（最低版本声明 0.85.0）；源码构建成功不代表客户端、官网和云端已部署。协作层级统一为律所、团队、项目，个人是成员身份。业务分类、主办律师和律师个人是下列看板的统计维度。插件与律师工作台及律所业务管理引擎联动，提供六大核心模块：

1. **收案与立项（Case Intake & Progress）**：保留本机委托人、对方当事人、关联方/控股股东/一致行动人、主办负责人、业务分类与收费模式（固定收费、按标的额比例、风险代理、计时收费、常年法律顾问）登记、利冲与收费合规预检及本机建项。插件与个人中心共享这套本机台账，其历史五步进展不代表跨账户征询或委员本人已确认。
2. **利冲审查中心（Conflict Clearance & Committee Center）**：上方云端协作由总部团队 OWNER/ADMIN 指定委员，委员本人接受后生效。接受或拒绝必须携带所见邀请版本；旧页面不能接受撤销后重新发出的邀请，成功请求的原版本重试保持幂等。通过手机号或邮箱核验同所、已连接官方案件库的真实账户；申请人明确发送后，仅新协作记录进入官方云端，并只检索同所已主动提交的云端申请。关联律师收到仅与本人有关的征询摘要，并可查看本次申请标题及双方名称；其他律师的旧案名称不向其开放。全部放行后由指定委员人工终审；通知已读不代替接受或决定。云端终审结果不自动创建本机项目。下方保留原本机核查与演示台账，其本机站内信记录不代表跨设备送达；既有财务数据不会自动上传。
3. **发票与财务收费（Invoicing & Fee Collection Ledger）**：支持数电专票、数电普票、增值税专票/普票申请与开票确认；在未接通外部 ERP 前支持手动登记收费到账与发票核销，同时提供金蝶/用友标准财务台账同步接口。
4. **决策与业务看板（Decision-Maker & Workload Dashboard）**：按业务分类、主办律师与律师个人汇总在办案件、工作负荷指数（空闲 / 适中 / 饱和 / 超负荷）、签约合同额、已开票额、已到账实收、待收账款 AR、开票率、账单回收率、合同回款率及应收账款账龄分布（`<30天`、`30–90天`、`>90天`）。既有 `departmentName`、`teamLeads`、`units` 接口字段保持兼容，其中 `units` 对应律师个人，`teamLeads` 按主办律师归组。
5. **办案费用（Matter Expenses）**：0.1.4 新增的本机台账（插件 storage，宿主上限 64 KB），登记诉讼/仲裁费、保全费、鉴定评估费、公证翻译费、差旅、调档、邮寄复印等费用，区分律所代垫与委托人直付。按事项汇总代垫金额、待向委托人结算金额及其中缺凭证金额，可逐笔标记已结算。依《律师服务收费管理办法》，结算时须提供代付费用清单及有效凭证，故缺凭证单独提示。办案费用与律师费发票分开记录，不进入「发票与财务收费」台账，也不上传云端。
6. **计时收费（Hourly Billing）**：0.1.12 新增，宿主 0.85.0 起可用，与「办案费用」一样只在桌面端本机台账。律师不另填工时表：在宿主「设置 › 工作记录 › 计费工时」把工作记录（活动记录器按文件/网页会话写入、已扣空闲、带项目）按「项目 × 天」生成草稿工时，改描述、改时长、标可收费或手动补录后提交审核。插件「计时收费」页供主办律师或合伙人按月、按客户与事项审核：核减（须写理由，不能超过申报）、改描述、标为不收费、退回律师、通过，每一步记入审核记录，律师在工作记录里看到结论与理由。费率按律师级别设所内标准费率，事项可按级别约定费率、折扣与累计封顶；通过时把适用费率与标准费率固定在工时上。已通过的可收费工时一键生成账单（明细快照、先折扣后封顶），发客户确认后登记确认人，系统调用原「发票与财务收费」的发票申请接口生成一张待开票申请，开票和回款核销仍在原台账办理，不另设财务账。管理者按律师看申报、可收费、核减及不收费、未出账单工时，以及实现率（实际收到 ÷ 按标准费率应收；只计账单客户已确认或审核时标为不收费的工时，实收取核销到该账单发票的真实回款，按各条金额比例用最大余数法分摊到律师）。金额全部以分为单位、BigDecimal 计算：工作记录按 6 分钟向上取整（不足 1 分钟不生成），手填小时最多两位小数；单条金额 = 分钟 × 小时费率 ÷ 60 四舍五入到分；折扣四舍五入到分。客户维度目前取自收案登记的委托人名称。

## 构建与验证

执行 `./official-plugins/lawfirm-management/build.sh`（先由 `l10n/*.json` 的 `expense.*`、`access.*`、`billing.*` 键生成 `web/expenses-l10n.js`，再跑测试）。测试复用 `frontend` 安装的 `jsdom` 运行合成沙箱回归，并将仓库 `sdk/plugin-sdk/awd-plugin-sdk.js` 打包输出至 `dist/lawfirm-management-0.1.12.zip`。云端依赖 `LawFirmWorkflowService`、消息中心及官网名录的 `firmAdmin` 权限事实；旧名录缺该事实时默认不能指定委员。新增三张业务表及一张仅保存律所 ID 的扫描锁表，由既有 Hibernate schema update 创建，不迁移旧律所表。同所提交在数据库行锁下完成扫描、建单和通知；首行创建唯一冲突在独立事务回滚后重读。自动扫描的旧案名称及命中主体只返回给关联律师本人。测试 `LawFirmWorkflowTest` 使用四种业务身份及另一律所身份，不使用 localMode 代确认；真实账户跨设备送达与 PostgreSQL 环境仍需部署前后分别联调，H2 PostgreSQL 模式不视为 PostgreSQL 实测。
