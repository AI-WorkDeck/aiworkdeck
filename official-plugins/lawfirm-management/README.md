# 律所管理

官方律所全业务管理 Web 插件，0.1.15 需要具备云端利冲协作及消息中心 API 的宿主（最低版本声明 0.82.0；客户管理需要 0.86.0 起的宿主，较早的宿主上「客户管理」栏与收案的客户下拉自动隐藏，收案与利冲照旧；计时收费与「律所云端」页同样需要 0.86.0 起的宿主，较早的宿主上这两页自动隐藏）；源码构建成功不代表客户端、官网和云端已部署。协作层级统一为律所、团队、项目，个人是成员身份。业务分类、主办律师和律师个人是下列看板的统计维度。插件与律师工作台及律所业务管理引擎联动，提供七大核心模块：

1. **收案与立项（Case Intake & Progress）**：保留本机委托人、对方当事人、关联方/控股股东/一致行动人、主办负责人、业务分类与收费模式（固定收费、按标的额比例、风险代理、计时收费、常年法律顾问）登记、利冲与收费合规预检及本机建项。插件与个人中心共享这套本机台账，其历史五步进展不代表跨账户征询或委员本人已确认。
2. **利冲审查中心（Conflict Clearance & Committee Center）**：上方云端协作由总部团队 OWNER/ADMIN 指定委员，委员本人接受后生效。接受或拒绝必须携带所见邀请版本；旧页面不能接受撤销后重新发出的邀请，成功请求的原版本重试保持幂等。通过手机号或邮箱核验同所、已连接官方案件库的真实账户；申请人明确发送后，仅新协作记录进入官方云端，并只检索同所已主动提交的云端申请。关联律师收到仅与本人有关的征询摘要，并可查看本次申请标题及双方名称；其他律师的旧案名称不向其开放。全部放行后由指定委员人工终审；通知已读不代替接受或决定。云端终审结果不自动创建本机项目。下方保留原本机核查与演示台账，其本机站内信记录不代表跨设备送达；既有财务数据不会自动上传。
3. **发票与财务收费（Invoicing & Fee Collection Ledger）**：支持数电专票、数电普票、增值税专票/普票申请与开票确认；在未接通外部 ERP 前支持手动登记收费到账与发票核销，同时提供金蝶/用友标准财务台账同步接口。
4. **决策与业务看板（Decision-Maker & Workload Dashboard）**：按业务分类、主办律师与律师个人汇总在办案件、工作负荷指数（空闲 / 适中 / 饱和 / 超负荷）、签约合同额、已开票额、已到账实收、待收账款 AR、开票率、账单回收率、合同回款率及应收账款账龄分布（`<30天`、`30–90天`、`>90天`）。既有 `departmentName`、`teamLeads`、`units` 接口字段保持兼容，其中 `units` 对应律师个人，`teamLeads` 按主办律师归组。
5. **办案费用（Matter Expenses）**：0.1.4 新增的本机台账（插件 storage，宿主上限 64 KB），登记诉讼/仲裁费、保全费、鉴定评估费、公证翻译费、差旅、调档、邮寄复印等费用，区分律所代垫与委托人直付。按事项汇总代垫金额、待向委托人结算金额及其中缺凭证金额，可逐笔标记已结算。0.1.11 起「缺凭证」行可点「已补凭证」（记录补凭证日期，可选说明）：补后该行不再计入缺凭证金额与提示，可随时撤销；新增字段 `receiptAddedAt`/`receiptNote` 可缺省，旧数据照常读取。依《律师服务收费管理办法》，结算时须提供代付费用清单及有效凭证，故缺凭证单独提示。办案费用与律师费发票分开记录，不进入「发票与财务收费」台账，也不上传云端。
6. **客户管理（Clients，0.1.12）**：一个客户一张档案——基本信息、联系人、客户维护人与主办合伙人，以及名下全部收案/项目、开票回款、利冲记录与往来记录。客户与非客户主体（股东、实际控制人、供应商、配偶等）在同一份本机主体数据里，主体之间登记有向、分类型的直接关系（股东可填持股比例）；间接股东与下级子公司按股权链自动推导并显示链路与穿透持股比例。收案时可直接选已有客户，只填名称的收案按信用代码或规范化全称归到同一客户；利冲检索沿同一份主体与关系检索（对方当事人是本所客户、经关系链连到本所客户、或新委托人的关联主体是在办案件对方当事人），命中时给出关系链。客户列表即管理视图：按客户看在办项目、今年实收、应收账款与最近往来，可按维护人筛选、按「超过 N 天无往来」筛选。「最近往来」取真实信号：登记的联系、客户项目的工作记录、项目群消息、已过日期的会议/开庭日程、收案登记。旧版本的收案委托人在打开台账时自动归集为客户档案，收案上登记的关联方转为关系。与其他本机台账一样只在桌面端可用。
7. **计时收费（Hourly Billing）**：0.1.13 新增，需要宿主 0.86.0 及以上（旧宿主上「计时收费」页自动隐藏），与「办案费用」一样只在桌面端本机台账。律师不另填工时表：在宿主「设置 › 工作记录 › 计费工时」把工作记录（活动记录器按文件/网页会话写入、已扣空闲、带项目）按「项目 × 天」生成草稿工时，改描述、改时长、标可收费或手动补录后提交审核。插件「计时收费」页供主办律师或合伙人按月、按客户与事项审核：核减（须写理由，不能超过申报）、改描述、标为不收费、退回律师、通过，每一步记入审核记录，律师在工作记录里看到结论与理由。费率按律师级别设所内标准费率，事项可按级别约定费率、折扣与累计封顶；通过时把适用费率与标准费率固定在工时上。已通过的可收费工时一键生成账单（明细快照、先折扣后封顶），发客户确认后登记确认人，系统调用原「发票与财务收费」的发票申请接口生成一张待开票申请，开票和回款核销仍在原台账办理，不另设财务账。管理者按律师看申报、可收费、核减及不收费、未出账单工时，以及实现率（实际收到 ÷ 按标准费率应收；只计账单客户已确认或审核时标为不收费的工时，实收取核销到该账单发票的真实回款，按各条金额比例用最大余数法分摊到律师）。金额全部以分为单位、BigDecimal 计算：工作记录按 6 分钟向上取整（不足 1 分钟不生成），手填小时最多两位小数；单条金额 = 分钟 × 小时费率 ÷ 60 四舍五入到分；折扣四舍五入到分。客户维度目前取自收案登记的委托人名称。**跨电脑汇总（0.1.15 起，需要宿主 0.86.0 及以上）**：律所管理员在「律所云端」页开启「计时工时汇总」后，合伙人把本机收案「发布到律所云端」（只上传事项名称与委托人名称），其他电脑上的律师在计费工时里选该云端事项提交；合伙人「从律所云端取回工时」，在本机台账里照常审核、出账单，结论自动回写，律师在自己的工作记录看到。费率、金额、账单、发票与回款不上云，本机台账仍是唯一的财务账。原「确认开票」按钮会填一个占位发票号，现改为必须在「申请单号 / 发票号」一格填写开票系统返回的真实号码；台账每行新增「作废」（未开出）/「红冲」（已开出），点两次才执行。客户已确认的计时账单要先作废或红冲对应发票才能撤销。

**律所云端（0.1.14 起）**：「律所云端」页集中列出本所各项云端功能（客户与主体、计时工时、投标材料等，以所连接协作服务已登记的为准）的开关。开关按律所保存在官方协作服务（或自建团队服务器）上，默认全部关闭，只有律所管理员能改；修改时带上所见版本，另一位管理员刚改过会提示刷新。关闭时可选择同时删除云端已保存的该项数据。各功能页只显示状态并链接到这里。收费金额、发票与回款始终只在本机台账。

## 构建与验证

执行 `./official-plugins/lawfirm-management/build.sh`（先由 `l10n/*.json` 的 `expense.*`、`access.*`、`client.*`、`billing.*`、`cloud.*` 键生成 `web/expenses-l10n.js`，再跑测试）。测试复用 `frontend` 安装的 `jsdom` 运行合成沙箱回归，并将仓库 `sdk/plugin-sdk/awd-plugin-sdk.js` 打包输出至 `dist/lawfirm-management-0.1.15.zip`。云端依赖 `LawFirmWorkflowService`、消息中心及官网名录的 `firmAdmin` 权限事实；旧名录缺该事实时默认不能指定委员。新增三张业务表及一张仅保存律所 ID 的扫描锁表，由既有 Hibernate schema update 创建，不迁移旧律所表。同所提交在数据库行锁下完成扫描、建单和通知；首行创建唯一冲突在独立事务回滚后重读。自动扫描的旧案名称及命中主体只返回给关联律师本人。测试 `LawFirmWorkflowTest` 使用四种业务身份及另一律所身份，不使用 localMode 代确认；真实账户跨设备送达与 PostgreSQL 环境仍需部署前后分别联调，H2 PostgreSQL 模式不视为 PostgreSQL 实测。
