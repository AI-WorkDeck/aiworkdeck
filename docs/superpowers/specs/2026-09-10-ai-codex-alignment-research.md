# AI 交互对齐：现状、官方实践与设计草案

日期：2026-09-10。状态：调研完成，设计待确认，尚未修改产品代码。

用户目标：四层可见、可写的 Markdown 记忆；取消固定工具调用次数上限；执行中可补充指令和调整方向；整体对齐 Codex 的任务交互。

## 1. 调研边界与基线

- 检查了当前工作目录与最新远端主线。当前分支 `codex/local-desensitize-restore`，HEAD `5c0da2d6`，含本地脱敏等工作；最新主线为 `5129e9bc4d49308e47e8abfa6ff77e90b51fe643`。两者差异较大，不能直接在旧基础上覆盖主线编排器。
- 以下最终结论以该主线快照为准；实现应在最新主线的独立工作区进行，再按交付需要整合当前分支工作。
- 本文是代码路径与官方文档对照，不是运行中的产品截图审计，也没有验证生产部署版本。未执行真实付费模型对话，未运行变更后的测试。
- 对齐范围为用户从提交任务、执行中交流，到成果查看和后续工作的完整链路。产品仍以法律文档和项目为中心；Codex 的代码工作树、终端等开发功能仅作为可选参考，不作为本轮必须复制的界面。

## 2. 已核实的现状与差距

下列代码定位均相对于上述主线快照。

| 用户动作 / 能力 | 当前实现 | 差距及建议 |
|---|---|---|

| 切换 / 新建对话 | 页面卸载只断本地连接；但 `ChatInterface.startNewChat` 1438 附近会 abort 旧任务 | 统一为离开视图不等于停止任务，新建对话也不自动取消旧任务 |

| 长上下文 | `RunLoopCompactor` 已剪长工具结果、折叠历史，并有溢出后强制压缩 | 复用；额外保护原目标、最新补充、未完成事项、必要记忆索引和工具结果配对 |
| 防止重复打转 | `StuckDetector` 检测同参重复与 A/B 交替；编排器拒绝执行后仍给模型反馈继续循环 | 取消轮数上限后必须让持续无进展真正暂停；合法轮询不能仅因同参重复而误判 |
| 计划与提问 | 已有 ASK / PLAN / AGENT、计划、todo、QuestionCard 和等待输入状态 | 保留现有组件；状态明确区分建议计划、等待决策和继续执行。提问应保留原任务，不把补充或状态询问当成替换任务 |

## 3. 官方实践与可采用的结论

### 3.1 Markdown 记忆

Claude Code 的自动记忆使用简短 `MEMORY.md` 索引和主题文件，索引在会话开始加载，主题文件按需读取，用户可查看、修改、删除。文件名采用 `remember.md` 是本产品约定，不要求照搬官方名字。[Claude Code memory](https://code.claude.com/docs/en/memory)

Anthropic Memory Tool 让模型请求文件操作，应用掌控存储；路径可映射到目录或数据库。适合本项目沿用自有后端，无需为记忆更换模型供应商。[Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)

Codex 区分长期指导与自动记忆，自动生成可在后台延迟进行；不要把所有强制规则都依赖自动召回。其生成文件也不是官方推荐的主要手动编辑界面。本产品的“用户可直接编辑 Markdown”主要借鉴 Claude 的交互，并作为自身产品契约。[Codex memories](https://learn.chatgpt.com/docs/customization/memories?surface=app)

### 3.2 循环上限

Claude Agent SDK 仍提供 maxTurns 和成本预算选项，官方表格写明两者默认不限制。OpenAI Agents Python SDK 明确支持 `max_turns=None` 关闭轮数限制。因此准确说法是“可以不设固定轮数”，而不是所有 SDK 已经删除该能力。[Claude agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop#turns-and-budget) · [OpenAI running agents](https://openai.github.io/openai-agents-python/running_agents/)

建议默认不设总轮数上限；继续保留用户停止、单次请求超时、重试预算、现有账户额度、权限检查和无进展处理。并行任务数量属于资源管理，不等于单次对话调用次数，不应一并放开。

### 3.3 调整方向与排队

Codex 官方将 Steer 定义为加入当前 run，Queue 为留到下一 run；运行中可以继续提交。桌面端支持默认行为设置，队列可编辑、排序、发送、删除。[Codex prompting](https://learn.chatgpt.com/docs/prompting#steering-and-queuing)

OpenAI 另有模型层 mid-turn steering，但当前文档限定特定模型及 Responses WebSocket。收到 accepted 也不等于已应用；不会回滚已输出的内容、撤销已发生的动作或自动取消在途工具。现有产品使用多模型通道，先实现供应商无关的编排器收件与安全边界注入，模型原生能力可后续按支持情况接入。[Mid-turn steering](https://developers.openai.com/api/docs/guides/steering)

## 4. 推荐路径与取舍

1. **推荐：保留现有编排器与文档能力，补齐持久化收件箱和记忆文档服务。** 最大程度复用现有多模型、Office/LOWA、计费、取消隔离、压缩和流式协议，逐项交付。
2. 只改输入框、删除 30 常量：改动少，但没有队列、运行中输入的消费边界、组织权限、持久化与真正停机，不能满足目标。
3. 整体替换成 Claude / Codex SDK：可借用循环能力，但仍需自行处理四层权限、文档桥接和同步，且会改变现有多模型架构。本轮收益不抵迁移范围。

## 5. 推荐设计：四层记忆

### 文档与归属

每个具体用户、项目、律所、团队都有独立的记忆空间。下列路径为产品中的逻辑视图，不能作为绕过权限的磁盘路径：

```text
记忆/
  用户/remember.md      → preferences.md、writing.md
  项目/remember.md      → background.md、decisions.md
  律所/remember.md      → standards.md、templates.md
  团队/remember.md      → workflow.md、agreements.md
```

- Markdown 正文是用户和模型共同读写的内容。数据库负责归属、路径、正文、版本、修改者及来源；读取、编辑、下载和同步均走同一文档服务，避免“界面改了文件，下一次同步又被数据库覆盖”。
- 用户/项目空间沿用其现有存储与同步归属；组织共享空间由能校验成员身份的服务端统一管理，本地只是受权限约束的缓存。四个本地目录本身不能算完成团队共享，也不能把不同机器上的本地数字 ID 当成同一个人或组织。
- 后端提供 list/read/write/edit/delete/search；支持相对 `.md` 链接。写入使用版本校验，冲突明确返回，不静默覆盖别人的修改。
- `remember.md` 包含简短关键记忆和主题链接。模型负责内容选择、总结、组织；后端原子维护目录链接的一致性与版本，拒绝跨域路径穿越。不要引入新的复杂打分或正则记忆提取框架。
- 现有条目可按稳定 uid 迁移为文档，保留原来源、保护标记及历史；旧 API 作为兼容入口调用同一写服务。旧检索索引可继续服务证据查询，但不再作为另一份可独立写入的记忆真源。
- Git 导入导出必须识别新索引和主题文件，延续墓碑防复活与跨机器稳定身份规则；不要求用户先配置远端才能本地看到记忆。

### 每次对话如何使用

- 每个用户消息启动任务时，后端注入用户和当前项目的精简索引与关键记忆。新对话、继续、压缩恢复都需覆盖。
- 已核实成员身份时，附上可用律所/团队空间的名称与精简索引；详细内容由模型按任务需要读取。索引按上下文预算控制，不能把四层全文每轮塞进系统消息。
- 新增补充被应用前，刷新涉及的索引版本；工具主动读到的新记忆即时生效，避免本轮保存后仍被旧索引误导。
- 明确说“记住”的内容通过工具即时写入，成功才显示“已记住”；自动沉淀由模型决定是否值得写，不必每轮固定调用额外模型抽取。
- 记忆提供背景，不凌驾于当前用户指令和权限；引用文件、网页中的指令不能变成系统规则。文件/对话绑定是项目记忆内部的来源或范围信息，不扩成额外组织层。
- ASK 模式目前禁工具：关键索引仍加载；需要读取更多记忆时应开放有权限的只读记忆工具，写操作仍遵循该模式规则，不能悄悄放开所有工具。
- 记忆工具纳入基础工具集，防止选择某个 skill 后被工具白名单意外裁掉。

### 权限和用户入口

- 用户层只属于本人；项目层按现有项目角色读写。默认不把个人或案件信息自动提升为团队/律所共享信息。
- 律所/团队 ID 从已验证账户归属获得，不信任模型或前端填入的任意 ID。最新主线 `OrgMembership` 已有 teamId/firmId，但现有名录接口只回归属，没有管理员角色；若采用管理员写权限，需要补充服务端可核实的角色能力。
- 共享写权限草案默认“成员可读、管理员可改”，已向用户询问偏好；最终确认时可改成“成员可读写＋版本记录”。两种都需要真实成员校验，不能凭同项目推导同团队。
- 成员退出、切换团队、删除记忆后，下一次读取或注入必须重新按有效身份判断；组织服务不可用时明确显示共享记忆暂不可用，不能默认为公共可读。
- 项目下提供“记忆”入口；设置页可查看用户与组织记忆。显示四个空间、`remember.md` 和主题文件，支持查看、编辑、删除、下载、版本。对话中的“已读取记忆／已更新记忆”可打开对应文件。

## 6. 推荐设计：执行中交流

### 用户操作

- 空闲时，Enter 发送任务；运行时，输入框仍可使用，默认发送为“调整当前方向”，另提供“完成后执行”。Shift+Enter 仍换行；不直接照搬 CLI 的 Tab，以免破坏桌面键盘焦点导航。
- 停止按钮独立存在，不再占用发送按钮。停止表示请求中断；在途不可取消操作显示“正在停止，等待当前操作结束”，不先宣称已经停止。
- 输入框上方显示待处理消息。补充显示“已收到 → 待应用 → 已应用”；排队消息可编辑、删除、排序、转为当前补充。
- “只回答我的状态问题”属于一次补充：简短回应后继续原任务。只有用户明确取消或替换原目标时，才舍弃未完成目标。

### 收件和消费

- 增加持久化会话收件箱：messageId、clientRequestId、conversationId、targetRunId、类型 steer/queue、正文与附件引用、顺序、状态、版本、接收/应用时间。
- 服务端先按用户/项目权限接收并落库，再回执；前端收到回执再清输入。重试使用相同 clientRequestId 幂等，防止网络重连重复提交。
- 同一会话最多一个消费者推进主循环。已有运行时按类型投递，不再覆盖式启动第二个消费者；其他会话可并行，但共同修改同一文档仍遵循文档版本/锁。
- 安全边界包括模型请求前、工具返回后、尚未开始的下一工具前，以及准备结束 run 前。接收与最终结束必须串行协调：最后一刻到达的补充由当前 run 消费，或可靠转入紧接的 run，不静默丢弃。
- 若已生成一批工具请求但还未全部执行，应用改方向前，不执行被新指令取代的剩余动作；为未执行请求补齐明确的工具结果，保持原生 tool-call/result 配对。XML 工具路径也需覆盖。
- 通用多模型路径不承诺修改已发出的模型请求。模型正在输出时显示待应用；到安全边界带入新输入。具备原生 steering 的供应商将来可缩短延迟，但不能改变回执与持久化契约。
- 历史顺序应保留“原指令 → 已完成的助手片段 → 新指令 → 后续片段”。不能向原助手气泡无限追加，以至于插入消息在历史中看起来发生在全部执行结束后。
- 事件增加 runId、messageId/片段 ID 和递增序号；支持快照与序号恢复，重复事件幂等，不让旧 run 的完成事件终结新 run。

### 队列、停止和恢复

- 当前任务正常完成后，按顺序自动开始下一条 queue 消息；ERROR、用户停止、等待必要回答或审批时队列保留且暂停自动消费。
- 停止按具体 runId 作用，不误杀下一轮；显示队列仍保留，由用户决定继续或修改。正在执行的外部副作用不能仅靠聊天状态回滚。
- 应用重启时先恢复收件与消费状态，将不确定执行标为中断；用户继续后核实文档版本和已完成动作再推进。目标是输入不丢、不会盲目重放写操作，不能宣称外部副作用严格 exactly-once。
- 新建或切换会话只解除视图订阅；后台任务通过历史列表状态点可见，回来恢复执行片段与收件箱。依赖 Office/LOWA 编辑器的任务等待宿主重连时必须明确提示。

## 7. 取消固定上限所需配套

- 删除普通任务 30 轮、过卷 120 轮及子任务 6 轮的强制结束语义，清理对应提示和测试；不以 100 或其他更大数字替代。
- 继续检查取消、单次网络超时、故障重试与当前账户可用额度。子任务保留并行池边界和可停止能力；总超时与工具超时分别标注，不能误称为调用次数限制。
- 防打转参考工具结果与进度变化；对轮询等待类工具按状态变化判断。提示调整后仍重复相同无进展模式时，持久化并以 `no_progress` 暂停，可供补充方向或继续；不能只回一句错误让模型永久空转。
- 每次压缩保留原任务、最新方向修正、未完成 todo、必要记忆和完整工具结果关系。
- 长任务运行日志和 SSE 恢复缓存不能无界增长；采用有界内存缓存与持久化片段。去掉总轮数后检查现有 executionLog/消息栈的增长与清理。

## 8. 分批交付与验收

| 顺序 | 交付 | 核心验收 |
|---|---|---|
| 1 | 单消费者收件箱、steer、queue、独立停止按钮、运行状态及历史片段 | 正在读文件/修改文档/输出答案时插入“先停修改，只列风险”，新方向被应用，未开始的旧修改不再执行；消息不丢且顺序正确 |
| 2 | 取消次数上限与无进展暂停、长上下文保护 | 用模拟模型完成超过 100 轮且有进展的任务，不因计数暂停；重复无进展可停；停止有效；正常轮询不被误伤 |
| 3 | 用户/项目 Markdown 文档、索引、自动注入、读写工具和用户入口 | 说“以后用简体中文”后用户记忆可见，换项目有效；项目事实不会带到无权项目；编辑/删除后新对话使用新状态 |
| 4 | 律所/团队空间、真实成员权限与同步扩展 | 同团队可读、异团队不可读；退出后不再注入；版本冲突不覆盖；不把用户私人记忆混入项目/组织检索 |
| 5 | 全链路回归与体验整理 | 新建/切换不停止后台任务；队列可编辑排序；断线/重启恢复不重复；计划、提问、附件、中文输入、Office/LOWA、skill 和已有成果回退能力正常 |

测试重点是竞态与权限，不能只断言“存在某个按钮或字符串”：

1. 原生工具和 XML 工具两条路径：提交、最后一轮收尾、取消、重试、断线重连分别插入新消息。
2. 相同 clientRequestId 重发；两个客户端提交同一会话；旧 run 在新 run 后迟到的输出与终态。
3. 提问/审批未回答时队列不推进；停止时队列不自动开始；重启时已接收未消费消息保留。
4. 记忆 ID 越权、跨域链接、旧检索旁路、管理员角色失效、并发编辑及删除后同步防复活。
5. 超过 100 轮的正常任务、真实无进展、结果变化的合法轮询，以及压缩后仍遵循中途修正。
6. 使用现有取消、恢复、压缩、memory scope、sync round-trip 测试作为回归基础；再在运行界面完成上述关键路径走查。
