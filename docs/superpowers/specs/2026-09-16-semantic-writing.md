# AI WorkDeck 语义补全落地计划

2026-09-16｜建议方案 v0.1｜范围：各类文书共用能力；诉讼、合同、尽调/法律意见三条专业线同时推进

本文件是可实施的方案，不代表下述能力已经开发或验证。本轮核对了现有源码，并让三个 Workflow 分别设计专业场景；未修改产品代码、调用付费模型或上传项目材料。

## 1. 目标与判断

可以实现现代 IDE 的主要交互和上下文辅助机制：知道当前对象是什么、在哪里有效、当前位置可能需要什么，并给出可接受或拒绝的建议。法律文书没有编译器可以判定的完整真值体系，因此“建议有依据”和“法律判断正确”必须分别验证。

推荐采用本地规则与可核实资料、按需模型生成相结合的方案。纯模板方式难以覆盖自由表述；每次输入都让通用 Agent 读取整个项目，速度、费用和事实控制难以满足补全。首期不训练基础模型，也不要求采购海量文书。

参考：VS Code 的 IntelliSense 将词语补全和语言语义服务区分；AI 行内建议及下一处编辑又是另一层能力。我们也应分层建设，而不是用一个生成接口承担全部职责。

- https://code.visualstudio.com/docs/editing/intellisense
- https://code.visualstudio.com/docs/editing/ai-powered-suggestions

## 2. IDE 能力在法律工作中的对应

| IDE 能力 | 法律文书对应 | 具体行为 |
|---|---|---|
| 类型 | 主体、角色、金额/币种、日期、定义词、条款、证据、观点 | “付款金额”位置优先显示金额，不混入公司名称；金额同时携带币种、单位和来源 |
| 作用域 | 权限、项目/交易、文书、章节、附件、定义范围、业务时点 | 甲方不能简单等同于原告；附件中的定义不覆盖主合同；别的项目事实不得混入 |
| 符号表 | 稳定主体 ID、全称、简称、角色绑定 | 更改简称后仍知道它指向同一主体；两个同名主体分开 |
| 依赖检查 | 事实与来源、条款与定义、金额与计算条件之间的关系 | 改付款比例后指出可能受影响的金额或条款，提供修改建议 |
| 代码补全 | 正确的名称、字段值、已有标准表达 | 高频操作在本地完成 |
| 行内/下一段预测 | 根据当前章节、写作立场和已取得材料续写 | 生成一句或一段，列出依据，接受前不改正文 |
| 下一处编辑 | 发现其他受影响的定义、交叉引用、同一事实表述 | 展示位置和差异，逐项确认；不自动跨文档替换 |

## 3. 已有底座与真实缺口

核对实现：本轮已合并的补全改进 PR #870 对应源代码；本文不假定安装客户端已包含它。

已有可复用能力：

- 本地词库、项目/用户隔离、文档实时抽词、类型标签和显式资料查询。
- 项目主体标签及别名、文档实体抽取、证据来源链接与部分确定性校验。
- 实时正文的段落索引、标题层级和 revision；安全光标快照、接受前校验、一次撤销。
- 模型供应商解析、流式响应、用量归属和模型配置。

必须补建：

- 角色/定义范围/事实状态/时点的统一结构；现有 kind 不等于语义类型。
- 来源的稳定片段定位、内容版本和更新失效。现有 DocInsight mention 的 paragraph 为 null；按文件名匹配不能当证据支持。
- 面向编辑器的增量索引。现有项目全文搜索会遍历文件，不能直接放进每次按键路径；旧 RAG 组件存在也不代表已有可直接复用的低延迟检索链。
- 句段候选的预览与接受协议。现有 accept_completion 只补真实前缀的后缀，禁止换行，不能直接接任意模型输出。
- 可取消、有限输出、短超时的补全模型请求。现有流式 generate 没有返回供补全调用方取消的请求句柄，不能把隐藏弹层当作已经停止计费。

## 4. 共享底座：三条线只建一套

### 4.1 项目事实与定义

最少结构：

- 对象：稳定 ID、名称、别名、类型。
- 关系/陈述：谁、什么属性/行为、值、单位、币种、日期及时间含义。
- 范围：项目/交易、文书、章节或附件、角色和代理立场。
- 来源：文件 ID、内容版本或摘要、页/段/单元格定位、原文摘录、取证或检索时间。
- 核对状态：未核对、已核对材料、人工核实；保存核实人、时间、方法与覆盖的版本/事项。
- 陈述类别与归属：合同约定、材料记载、我方主张、对方主张、裁判认定、分析推断；保留叙述主体与适用时点。
- 来源健康与冲突：可用、过期、失联、相互冲突；与前两类状态分别保存，不能用一个“已确认”或 confidence 数字混合替代。现有 EvidenceLink.status 只表示关联健康，机械核对 supports 也不等于律师已经核实。

“律师确认来源里有这句话”“对方承认这项事实”“裁判认定这项事实”不是同一个状态。接受某句补全，只表示选择这段文字，不自动把它升级为已核实事实。

复用既有主体标签/别名/变量，避免再造一份互不一致的主体名册。系统先从项目材料和当前文书抽取，用户仅确认重要角色、冲突和缺失项；不要求先填完整案件数据库才能写作。

### 4.2 上下文组织

权限与项目范围先做硬过滤；随后按文书局部定义、章节任务、当前输入、已确认主体/事实、相关材料片段排序。个人词库或跨项目模板只能提供通用措辞，不能携带另一个案件的事实作为本案依据。

文书没有正确标题时允许推断章节，但给低确定性结果；遇到冲突就降级或列出待确认项，不强行选一个。引述对方意见的段落不能被默认改成我方立场。

材料导入、保存、替换、删除、版本切换和权限撤销都要使相关缓存失效。未保存正文以编辑器 revision 为准；外部文件以其内容版本为准。首版为选入的资料集建立轻量段落/关键词索引，必要时增补向量排序，先验证检索质量，不预设必须部署大型向量基础设施。

### 4.3 两条响应路径

- 本地路径：主体、定义词、确认字段与已有表达。打字即时筛选，不调用模型。
- 生成路径：用户主动请求，或明确开启停笔建议后，取有限相关上下文生成一句；下一段默认主动触发。低延迟模型与较强模型分别承担短句和段落任务，从已有可用模型中实测选择，不写死“最强模型”。

生成路径复用现有账户/模型路由和计费，不经过完整聊天 Agent 的反复工具调用。外部法规/工商查询独立请求并缓存成功结果，不跟随每个按键查询。模型失效、无额度或慢响应时本地补全继续可用。

每个编辑器只允许一个当前生成请求，设置停笔门槛、输出长度、冷却与每日成本上限。前端过期即丢弃，后端尽力取消实际请求；取消后的真实消耗仍记账。正式选模型前跑相同回放集，比较首个可接受建议耗时、正确性和每百条保留建议的成本。

### 4.4 预览与接受

统一请求携带项目/文件/会话、文档 revision、光标锚点、前后文摘要、文种/章节/立场、事实集版本、允许的来源范围。

统一候选携带种类（词条/字段/句子/段落/修改）、显示文本、插入或替换范围、事实 ID、来源引用、事实状态、冲突/缺失项以及有效的上下文版本。结构化输出后还要验证；JSON 格式正确不代表内容正确。

首版短句使用光标附近的紧凑预览，选中可展开来源；可在 LOWA 排版覆盖层验证通过后加真正的灰字预览。预览内容不写入正文、不进入导出和修订。不能先把生成内容写入正文再靠撤销伪装灰字。

接受入口先重新检查项目权限、权限版本、sourceSetVersion和所引用来源的健康/内容版本，不能只依赖异步失效事件；检查通过后引擎内同步复核位置、原文和文档版本再落字，晚到或已过期结果拒绝。一致性以本次服务端授权快照为界，不能声称后端与WASM是一个跨进程事务；M0须验证两段校验间的变更/失败处理。一次接受对应一次撤销。多段、表格、修订模式、脚注等分别验收，不直接取消现有安全限制。预览来源先可点击定位；如后续持久化证据关联，另定义文档编辑与后端数据库的失败补偿及撤销语义，不能假定是一个原子事务。

## 5. 三个 Workflow 并行交付

三条业务线同时支持，按相同深度升级；不要求某一类用户等另一类做完。共享接口由主任务维护，业务线各自实现文种配置、候选生成/校验、样例和验收，不重复修改公共插入协议。

| Workflow | 第一层：类型与作用域 | 第二层：有依据的一句话 | 第三层：段落与关联修改 |
|---|---|---|---|
| A 诉讼文书 | 当事人及诉讼角色、立场、证据编号、主张/争议状态 | 根据指定证据表述签约、履行等事件；保留“主张/记载”等归属 | 事实段、争点回应的候选草稿；变更主体/请求后提示相关表述 |
| B 合同 | 本文档甲乙方、局部定义、金额单位、条款编号与版本 | 按已确认交易条件起草短条款；明确这是约定而非已履行事实 | 条款组、备选措辞；改期限/金额/定义后列出受影响引用 |
| C 尽调与法律意见 | 交易范围、目标主体、核查事项、材料来源、截止日与版本 | “根据某材料记载…”；材料缺失或冲突时保持限定 | 按“材料—发现—分析—待核实事项”组织段落；更新材料后标出受影响结论草稿 |

这些是首批专业验收范围。其他文种仍可使用共用补全；未完成专业适配的类型不得冒称已有专门的法律判断能力。

### 三条线的可演示验收例子

以下都是合成测试，不构成实际案件判断。

- **A：主张金额。** 用户已确认按合同120万元减已付40万元主张80万元。输入“支付剩余货款”，建议“人民币800,000元”，来源卡列算式和请求表；被告另主张现金付10万元但存在争议时，提示争议，不静默改成70万元，更不据此补出“从未支付”。
- **B：合同约定。** 当前合同总价12万元、第二期比例30%。输入“第二期价款为”，建议“人民币36,000元”，可查看条款和算式；不会续写成“已经支付”。旧合同的甲乙方角色反转不影响本份合同。
- **C：核查缺口。** 核查清单列有资质材料但尚未取得。输入“截至核查截止日”，可以建议“尚未取得清单所列材料，相关事项待补充材料后核查”；不会写成“没有资质”。两个相同基准日的设备清单写12台、15台时并列差异，不凭上传先后选15台。

三条线都需要正常、缺失、冲突、过期四类测试；代理词另测我方/对方意见归属，合同另测附件局部定义，法律意见书另测核查范围与截止日。

## 6. 里程碑与分工

以下为初步工程排期，不是完工承诺；三个 Workflow 并行，主任务负责共享接口、集成和整体审阅。预留约 4–6 周首版开发与验证窗口，M0 后用实测结果复估。

| 阶段 | 交付物 | 进入下一步的条件 |
|---|---|---|
| M0 技术验证，约 2–3 个工作日 | 三类各一套合成项目；冻结首批回放点；测上下文取得、请求取消、句段安全插入和真实显示时间 | 明确 LOWA 支持范围；选出可行预览与接受路线；给出真实延迟/费用基线 |
| M1 共享语义底座＋三线类型适配，约 1 周 | 对象/角色/定义/来源状态；局部缓存；三线字段候选 | 跨项目和角色反转测试通过；来源版本更新会失效；无需模型仍有价值 |
| M2 三线短句建议，约 1–2 周 | 有限检索、结构化生成、来源预览、确定性核查、取消和费用 | 保留测试集上的来源/数值/状态核查通过；延迟达标才开自动停笔建议 |
| M3 三线段落与关联修改，约 1–2 周 | 手动下一段；定义/数字/引用变化后的修改列表；原子接受与撤销 | 不凭空新增事实；多位置修改逐项可审；支持的编辑模式逐一跑通 |
| M4 试用与收敛，约 3–5 个工作日 | 三类真实脱敏工作样例；错误分类、性能分布和成本报告 | 律师验收并确认可发布范围；发布另按既有流程授权 |

公共底座先给稳定契约与测试桩，三条线即可并行；集成时由主任务统一合入。产品原有本地补全始终作为可回退路径。

## 7. 可检验的目标

以下是拟定发布门槛，M0 后确定环境、样本与阈值；不是目前已测结果。

- 每类至少 50 个冻结输入位置；三类之外另有跨项目、冲突、过期、缺材料和权限反例。开发用例与验收留出集分开，不把同一成品文书的续文当检索材料泄漏答案。
- 确认主体/定义候选 Top-3 命中率目标 ≥95%。每类另设至少20个“不该建议”的冻结负例，覆盖空上下文、纯模板、缺条件、角色未确认和来源冲突；关键条件缺失/冲突时自动路径确定性字段或事实建议为0。其余无关建议误触发率初定≤5%，M0按标注定义复核。按文类和困难子集分别报告，不用容易题拉高总分。
- 受控反例集中跨项目事实混入、角色颠倒、修改落错位置：0 次。有限测试零错误不是线上零风险承诺。
- 所有事实性生成陈述有可打开来源或明确主张归属；金额/单位/日期准确率目标 100%（受控样例），有来源但不支持其结论仍判错。实际材料随机样本由律师判定支持程度，不以模型自评分替代。
- 正文输入到本地候选可见：warm 路径目标 P95 ≤250ms；至少 200 次端到端测量，另列首次打开、长文、不同输入法/机器。旧版约三分之一秒的少量样本不足以证明达标。
- 停笔到首条可接受短句目标 P95 ≤2 秒；包括触发等待、检索、生成与校验。达不到就先只提供手动请求；段落不用短词条的速度标准冒充“即时”。
- 接受后保留率、接受后修改/撤销率、律师发现的事实错误、每百条保留建议成本均记录。接受不等于正确；默认只记录本地必要指标，不上传原文。

## 8. 用户和其他模块怎样配合

### 用户最有价值的投入

1. **每类一套可用于开发的脱敏/合成项目材料，加一份你认为写得好的成品文书**。起诉状/代理词配其证据材料；合同配交易条件和一轮修订；尽调/法律意见配核查清单和底稿。真实材料范围未确认前用合成材料即可推进。
2. 每类指出 5–10 个“我写到这里，最希望它接什么”的位置，以及不应出现的答案。我负责整理成测试，成品的后半段只作答案，不默认喂回检索。
3. 确认三类的写作偏好和禁止推断事项。系统自动提取，你审核主体角色、立场、合同确认状态、核查截止日等少量关键项，不要求手工标完整数据库。
4. 明确哪些项目可用云端模型、哪些只在本机处理，以及试验费用上限。现有云通道可复用；无需重新提供密钥，不先替你购买或训练模型。
5. 每个里程碑安排约 30 分钟看三类真实操作，判断“这条建议是否帮我少查一次资料、少改一次错”。

### 其他模块的交付责任

- 项目/文件：稳定 ID、主体别名、文书/附件归属、版本与权限变更事件。
- 解析/OCR：可定位的段落/页/表格片段；解析失败和不确定内容保留状态，不能静默填补。
- 检索/证据：先按权限/项目/时点筛，再匹配；来源内容变化使旧候选失效。
- 模型/计费：快速与段落请求路由、真正的取消句柄、输出与超时限额、正确用户归属和实际消耗记录。
- 编辑器：局部实时上下文、纯预览、版本校验后一次接受/撤销；三条业务线不直接写文档。
- 律师验收：事实归属与法律表达的专业判断；不靠“读起来像真的”通过。

## 9. 首版明确不承诺

不自动判断诉讼必胜、不把检索命中等同于事实成立、不无提示地采纳对方版本、不自动发起外部付费查询、不自动批量改写其他文书。不通过训练用户全部案件材料来替代上述结构和验证。

下一步开发顺序已经可以按 M0 开工；首先冻结共享接口和三类验收样例，三个 Workflow 同时推进。当前本轮产出是计划与只读审计，尚未开始 M0 产品实现。

## 10. 开发落点与已核对证据

以下为拟复用/扩展的现有模块，不表示新能力已经接通。
