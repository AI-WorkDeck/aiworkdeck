# 云端逾期清理与本机隔离专项设计（仅设计，未实施）

依据用户当前政策：全部按量，可后付费；赠送额度之外给等额授信；超过授信 3 天未付提醒，5 天未付清清云端，不动本机。以下时间起点及清理边界需产品定稿，不擅自补成既定规则。

## 已核对的代码证据

- `backend/src/main/java/com/checkba/service/mobile/MobileBackupService.java:149-185`：删除先置 pendingDeletion；每60秒后台清理在账户锁下重新读取当前行，确认 blob 不存在后才删收据。可复用“先持久化删除收据再操作存储”的机制。
- `MobileVersionObjectService.java:199-225`：revoke 批量标待删，分块与完成收据独立存在，删除失败留收据重试。
- `MobileRelayClientService.java:474-540`：桌面备份是本地文件树→云端列表比较后上传。云端文件消失不会直接删除本地，但会被下一轮重新上传；清理后必须阻断旧代次上传，否则清理立即被填回。
- 同文件 1020 起 `pollMediaMoves` 会执行云端命令；`MobileCaptureMoveFiles.java:133-136` 确实可清理本机隔离文件。故欠费清理绝不可借用媒体 move/remove 命令、其 tombstone 或任何桌面删除链路。
- `MobileAssistantService.java:78`：关闭同意删除摘要和个人助理对话；调用结束另有 revision 校验，适合作为清理代次保护的参照。
- `MobileCalendarService.java:52`：关闭同步删除快照；`MobileCalendarPushService` 按 enabled/订阅状态发送提醒，清理冻结还须暂停提醒，处理已排队通知。
- `ProjectCatalogService.java:170-195`：云备份与本机目录镜像合并展示；不得把“云内容因欠费已清理”伪装成“用户删除本机项目”，目录镜像是否保留另定。
- `service/account/AccountDeletionService.java:149-195`：先注销统一账户，再清摘要、日历、媒体、设备、session、binding 和用户。不能复用整个注销流程来清欠费云数据，否则账单、支付入口、登录及身份全部被破坏。
- `ProjectService.java:371-446`：项目删除会经存储工厂删除真实路径及版本对象。欠费清理不能直接跨部署调用该方法；必须先证明项目和物理根目录属于云服务该账户，且没有共享项目授权冲突。

## 清理范围（候选，需定稿）

云端个人当前文件、回收站、版本对象全部分块和未完成上传、个人备份、现场影像中转、个人助理摘要/对话/来源派生索引、云端原生项目文件及其附件应纳入枚举。目录镜像、日历快照、通知设备令牌、会话元数据、用户原创对话、云端唯一副本、团队共享项目是否全部清除，必须形成明确产品清单；不能只删备份冒充“清空云端”。

始终保留：统一账户身份、支付及欠费账本、最小审计/删除收据、清理原因和进度。不得清本机项目、文件、Git/大对象、已下载手机文件；不得给本机推送 remove/move/tombstone。服务端法定留存或备份副本保留期与在线可读副本删除区别说明，不能宣称无法验证的彻底销毁。

## 建议状态机

正常 → 超授信计时 → 第3天提醒已发 → 第5天待清理 → 清理冻结 → 清理中 → 云内容已清理。

付款前几阶段可回正常；通知使用 episodeId+阶段 幂等键，多次重试不刷屏。触发时间由权威账本记录 exceededAt，不由客户端时钟或每天任务首次看到的时间决定。跨3/5天停机恢复时按账本时间判断，不能遗漏通知和清理前检查。

冻结取得账户操作锁，向权威账本核验未付清状态、账本版本和清理授权，再增加 cloudDataEpoch。后续上传/模型落库/同步/复制都要携带并核对代次；阻止旧请求在删除后发布。清理逐批操作、记录每项存储定位符和对象版本、先落收据再物理删除；进程崩溃重跑、存储不可用均留待重试，不能提前显示完成。只删除任务选定旧代次资源，不扫无边界存储前缀。

支付与物理删除跨系统无法仅靠一次“余额查询”原子化。需要账户中心的清理租约/提交协议：付款与清理授权串行，支付提交能撤销未执行批次；明确不可逆批次的提交点。已物理删除的数据不能承诺付费后自动恢复。剩余批次是否继续、付清后是否允许自动重传，需政策确认；建议停止未执行清理、保留本机，重新启用云备份时说明已删范围。

## 本机隔离约束

清理 worker 仅在官方云端启用；持有独立云数据删除能力，不调用桌面接口。存储定位符必须匹配可信账户所有者、云存储后端与任务清单，禁止客户端提交任意路径。协作项目按计费所有者及实际权限单独判断，不能删除他人的共享数据。清理状态是云能力状态，不是目录业务删除事件。桌面收到 cloudDataEpoch 改变只停止上传/显示提示，不删文件、不清本机版本；账户切换丢弃旧响应。恢复后明确决定是否重传，避免无提示再次生成费用。

## 验收矩阵

1. 第3/5天边界、时区、停机补跑、重复任务与重复提醒；临界账单冲正/退款。
2. 付款发生在扫描前、冻结前、首个删除前、批次中、全部删除后；不漏还款、不对已还清账户开启新删除，不虚假恢复。
3. 清理与上传、备份分块完成、模型回包、复制、日历同步并发；旧代次全部不能复活云数据。
4. 对象删除超时、部分成功、数据库回滚、worker崩溃；收据保留，重试幂等，完成状态真实。
5. 本机离线/在线、手机已下载/未下载、桌面重连；清理前后本机正文与版本 hash 完全一致，无删除命令。
6. 两账户相同文件 hash、同名目录、共享项目、账号切换；清理严格隔离。
7. 零字节文件、未完成块、回收站、云端唯一副本、摘要/附件/日历/临时中转全清单验证。
8. 付清后只恢复可恢复能力，已删内容如实标识；确认重新备份的计费与范围。

## 待确认政策

“超过授信”的起点是使用金额首次超过上限还是到达上限？之后3/5天允许继续消费还是停止新增？3天是否必须实际送达才起5天？部分付款降到授信以内但未全清是否停止清理？“未付清”指全部欠款还是超授信部分？赠送额度为零是否授信零，赠送额度变化是否追溯授信？云端唯一副本/共享项目和元数据范围如何处理？付清后的自动重传是否默认开启？这些均影响不可逆结果，不能由实现自行猜定。
