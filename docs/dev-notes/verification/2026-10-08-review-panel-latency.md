# 修订面板清单读取性能（dev-board#1136）

用户补充修订面板打开也非常慢。面板同时请求前500条修订及批注；本地历史存档测得 `list_revisions` 25,058ms，`list_comments` 2ms。纯分组逻辑的500条模拟数据为毫秒级，主要瓶颈在同步UNO清单读取，尤其段落定位、摘要及反复创建范围/文本/cursor代理。未从截图断言所有复杂文档都只有这一原因。

## 修改

完整清单保留原字段和500条上限。一次同步调用内复用正文对象、段落起止、最后命中段落及摘要；索引重建时清缓存。确认属于正文的范围用一个私有cursor读取正文跨度和段内偏移，每次先清旧选区，不移动视图光标。已有正文跨度长度可复用，隐藏删除文本长度仍不能充当正文零宽锚点的长度。连续区间比较先用正文对象，表格/页眉等其他story回原路径。缓存不跨命令、编辑或换文档；`locate:false`路径保持原行为。

## 实测与验证

同一本地历史存档、同一已安装0.53.1 r5引擎资源、隔离有头测试：最终worker清单读取3198ms，往返3287ms；批注2ms。相对先前25,058ms约减少87%。这是清单命令计时，不是升级后完整桌面客户端的可见面板首帧计时。原件只读，正文与截图不入库。

`test:lowa-review-list-performance` 使用49段正文+表格共500条交替插入/删除、3条批注。旧worker通过 `REVIEW_WORKER_SOURCE` 注入，`REVIEW_SNAPSHOT_OUT` 保存合成元数据；新worker使用 `REVIEW_SNAPSHOT_BASE` 逐字段核对，剔除每次引擎运行重新分配的修订identifier/批注id，其余字段完全一致。每次另断言500个唯一identifier、数量、段落上下文、正文定位及表格存在。

| 有头同环境 | 原清单命令链 | 修复后 |
| --- | ---: | ---: |
| all | 23,322ms | 4,309ms |
| balloons | 30,543ms | 12,530ms |

这些命令链时间包含显示切换后排队的工作，不能将balloons额外等待全部归因于单条清单命令。两态均通过15秒预算，旧实现均超预算。曾使用无头环境，出现明显耗时波动及一次Target closed；未以该次中断作为功能失败或提速证据，最终基线和复测统一用有头独立测试。

- 相关编辑器、修订视图和宿主单测1573项通过；最终cursor变更后编辑器/修订视图269项通过。
- 新单测锁定完整旧输出，并覆盖边界、跨段换行、隐藏删除零宽、表格及无Cell页眉回退、索引重建、一次正文cursor创建和foreign相接比较。
- 原生子代理参与实现，另一子代理对最终diff静态复核，无阻断问题。真实引擎对比由主任务执行，不称为跨agent独立实机复现。
- 完整基础引擎回归及CI结果后续见PR检查与台账落实记录。

未验证：安装更新后的用户客户端现场、Windows实机、其他引擎版本及所有复杂文档。修订面板仍受引擎同步读取成本约束，本次不承诺任意文档瞬时打开。未发版、部署或升级客户端。
