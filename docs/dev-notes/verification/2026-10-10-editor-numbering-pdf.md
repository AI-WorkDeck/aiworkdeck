# 编辑器编号、修订按钮与 PDF 预览验证

关联 dev-board#1176、#1177、#1178。仅源码交付，不发版或升级安装客户端。

## 根因与变更

- 自动编号不在段落正文内，旧审阅只看文字，遗漏自动编号与手写序号叠加。读取接口现在独立返回原生编号，结构审阅及行内审阅保留该元数据，正文偏移不变。项目符号、日期、金额、多级编号保留区分。
- 工具栏新增可选「版面检查」：选连续 1–6 页并确认耗时/用量后，导出当前内容为 PDF，再将选页渲染为图片交给视觉辅助模型。权限、文档归属、12MB 上限、单次调用、实际检查范围和过期结果均有明确边界。
- 0.56.0 安装包客体缺少 resolve_revision_at_cursor 白名单项，源码此前已修白名单；本次补全路由回归并修正 r5 原生修订起止区间倒置时的命中。没有替换为全接受。
- PDF 带有历史 wpsFileId 时被文字编辑器兜底误判。现在 PDF 始终走 PDF 预览，不改变 DOCX/ODT/表格路由。

## 实测

- JDK 21 后端定向测试 107 项通过：结构编号 19、审阅工具 4、行内服务 71、视觉服务/控制器 13。PDFBox 测试使用实际多页 PDF 并检查发送 PNG 的颜色、页码和 HIGH，模型响应为桩。
- LOWA 单测 143 项通过；前端 project-home 1351 项通过（后续新增关闭窗口竞态回归另测通过）。构建 h5、zetaoffice，emits/locales 检查通过。
- r5 原生编号验证：正文、十进制、多级列表、项目符号；30 次读取约 1828ms，读取不改变正文、光标、dirty 或 undo，DOCX 导出重开一致。
- r5 原生修订验证：插入/删除 × 行内/气泡 × 接受/拒绝 8 种情形；只处理命中修订，保留另一条修订，导出重开一致，无命中明确失败。
- 隔离源码 Electron：真实点击工具栏接受、拒绝，2 条删除修订变为 1、0，正文精确一致。真实点击版面检查，取消不请求；确认后导出实际 PDF，使用本机 HTTP 合成报告验证报告展示和页码范围。
- 同一 Electron 将上述 PDF 导入项目（含 wpsFileId），打开后确认走 PDF iframe。人工查看截图，中文三行正确、无 Word 工具栏或乱码。
- 第二视角发现关闭/替换编辑器发生于异步 revision 读取期间时可能继续请求或展示旧报告；新增回归先红，补齐 await 后 current 校验后转绿。
