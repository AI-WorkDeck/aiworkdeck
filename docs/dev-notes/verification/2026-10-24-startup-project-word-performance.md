# 启动、项目标签恢复与 Word 打开性能验收

2026-10-24（UTC），Codex desktop；台账 #1472 / #1473 / #1474，PR #1207。源码基线 `dd76721a6`，最终实现以 PR 合并记录为准。原有未提交工作树保持原样，全部修改和测试在独立工作树。此记录不代表已经发版或升级客户端。

## 改动与保护条件

- 启动只等待 Java 后端真实 HTTP 就绪，再创建主窗口；可选 Python 组件在主页面加载后启动。端口分配、后端失败提示、overlay 健康与回退、退出守卫保留。H2 模式直接返回原有内存向量库，跳过无效的模型维度探测及其重试，并避免 PostgreSQL 初始化；PostgreSQL 路径保留模型动态维度。
- 标签恢复只查询快照引用的文件 ID，每批最多200个；保持项目与文件树权限、软删除过滤及失效文件剔除。某批失败时不使用部分索引误删标签。请求同时保留 `tree=true`，旧后端忽略 `ids` 时仍能恢复子目录标签。常规文件树、标签及切项目保存顺序不变。
- Word 先隐藏原生外壳、应用视图偏好并回读真实状态，再读取字体和样式目录；移除设置前重复状态读取。热引擎已可装载时不再同时解析 DOCX 预览；冷启动、显式只读回退和死亡热备转冷启动仍提供预览，迟到预览受文档身份/世代/卸载检查保护。

## 标签核对接口

真实 H2/JPA 与 MockMvc，合成1万个文件，预热后5次测量中位数：完整树57.348ms、3037867字节；指定标签文件1.467ms、336字节。它证明恢复少量标签不再付出全量树读取/序列化成本，不能据此声称整个项目切换快39倍。

新增测试覆盖鉴权先于参数解析、CLIENT 拒绝、跨项目 ID、删除/不存在文件、目录、重复 ID、200项边界、非法值、原树/父目录和标签分支；前端覆盖左右窗格与比对文件去重、分批、空快照、失败时保留标签及旧后端子目录兼容。后端旧实现对指定 ID 用例转红，前端使用原实现也有负对照失败。

实际 Electron 回归又发现基线已有的存储接线缺口：普通 JS 方法组读到全局 `uni` 空壳，快照写入被吞掉；即使在 `.vue` 里赋值 `$tabStorage = uni`，裸标识符也不会被 H5 编译器替换。最终在恢复前注入具名 get/set 方法包装。行为测试执行真实 `onLoad`，模拟具名 API 改写但保留空全局；无注入、裸注入均转红，正确包装通过。最终编译产物也确认使用真实导入函数。

随后在隔离 Electron、新 H2、两个真实合成目录中，通过可见顶部切换器 B→A→B→A：子目录 `contract.txt` 标签恢复；输入标记时编辑器仍脏、磁盘尚无该标记，切走后真实上传成功，磁盘和切回后的编辑器都有标记。网络出现仅含目标文件的 `ids=2/4` 查询，本地存储有两份真实快照，截图人工核对。FileTree 自己的全树查询仍存在。此前失败轮次保留，并区分夹具导航/等待问题与真实存储缺陷；这些小样本 UI 操作不作为切项目性能基准。由于旧打包路径没有成功保存快照，接口基准更不能当成已测得的完整切项目前后对比。最终实测轮次为 `cold-after-switch7`，自然退出、退出码0、测试进程组消失，正式客户端端口归属未变。

## 真实 Word 引擎

QA 0.71.0 的 LOWA 与字体资源只读复用，当前源码胶水、隔离有头 Chrome、60段600处合成修订。测试直接调用实际 `EditorToolbar.vue` 方法；旧版使用 `TOOLBAR_SOURCE` 指向从基线提取的组件。新旧交替各3次：

| 中位数，均从 load_document 开始 | 旧实现 | 新实现 |
|---|---:|---:|
| 文档装载完成 | 1601ms | 1642ms |
| 编辑布局及真实状态就绪 | 2224ms | 1995ms |
| 字体、样式及整个工具栏初始化完成 | 2224ms | 2235ms |
| 首屏截图检查点 | 3151ms | 3165ms |

布局提前229ms（10.3%）；扣除装载后的布局初始化中位数623→360ms。目录仍完整可用，整体工具栏和截图检查点没有可确认的改善，不能将局部42.2%解释成整个文件打开快42.2%。首屏检查包含固定resize稳定等待和截图开销，不是精确首帧时间。

六次均通过纸张/墨迹像素、末部修订读取、实际鼠标悬停、导出后接受/拒绝全部修订的逐段原稿/目标稿还原。更早的首次布局查询曾返回6页370项、末索引369、`truncated=true`；诊断后确认异步分页继续到7页500项、末索引499。测试保留首屏时间，另按真实完成状态最多轮询5秒，原末索引>400断言保留；六次实际额外等待120–124ms。不是降低断言掩盖修订缺失。
