# Jev decision assist: scope and evidence

The user accepted a speed/cost tradeoff on 2026-09-23: modest extra latency is acceptable in exchange for lower token usage/cost. The composer switch is explicit and defaults off. This release candidate only preselects tool categories; it does not filter attachments, summarize conversation history, change the selected main model, judge legal correctness, or retry child agents.

## Runtime contract

- Only the original submission text (at most 4,000 characters) and currently eligible category/tool names reach Jev. Larger or ambiguous inputs keep the original path. Tool descriptions, separately attached documents and past conversation are not sent to Jev.
- ASK, absent consent, local-only providers, missing discovery tools, and small tool schemas skip the decision call. Skill-restricted tools retain their existing selection.
- One decision at most per run, no automatic retry, 2.5 seconds maximum caller wait including queueing, credential resolution and accounting. Unknown/low-confidence results, network faults and insufficient schema savings preserve the original path. The 0.8 confidence threshold is a heuristic, not an accuracy guarantee.
- An accepted result keeps core and memory tools, the chosen category and the discovery tool. Other eligible categories remain discoverable; execution permissions and the chosen main model do not change. The accepted set must remove at least 25% of serialized tool-schema characters; this is not a guarantee of billed-token or latency savings.
- Consent is stored with each durable inbox submission. Steering cancels pending advice and stops applying its narrowing; steering text is never added to the old decision request. Queued runs use their own snapshots. Cancelled/replaced runs cannot apply late advice.
- Platform requests use the user's platform channel and existing cumulative reconciliation; their receipt cost is not added twice. BYOK receipt costs remain in the separate local-statistics bucket. Channel changes cannot promote a local run to cloud.

## Validation and limits

A comprehensive audit covered context assembly, memory, tools, subagents, runtime guards and evaluation Harnesses. Context omission did not demonstrate latency gains; summary gating did not establish a need for remote classification over a simpler local tail-window design (that deterministic baseline was not implemented); one shadow delivery check did not establish reduced rework. Those candidates are not enabled by this switch.

Initial tool experiments compared full schemas, existing progressive disclosure, and Jev pre-expansion on two synthetic file tasks. Every group actually read the synthetic file and produced the predefined correct facts. Full-schema totals were 17.122 seconds / $0.005912625; progressive disclosure 41.375 seconds / $0.003213988; Jev pre-expansion 18.904 seconds / $0.001747995. These used production schemas with a safe Python file reader, not Java production execution. The files-specific prompt and simple path rule could produce the same narrowed set; do not attribute all narrowing savings to Jev or present those numbers as general product performance.

The exact general production prompt was then frozen before a separate 10-case classification evaluation. Labels were independently checked against the actual candidate list before any model results were read. Six decisions were correctly accepted, two intentionally returned uncertain, and two correctly labelled decisions fell below the confidence threshold and fell back. No wrong decision was accepted in these ten cases. Observed HTTP times were 1.186–1.884 seconds, with total Jev receipt cost $0.001463196. Those times exclude Java queueing/credential setup. The candidate set was LOWA with no active-document restriction; an early export named `docx` used an unrecognized document-kind value and must not be interpreted as a Writer-only candidate set.

A gated live Java test (`DecisionAssistLiveWorkflowTest`) exercises the actual decision policy, main model, registry and `FileTools.read_file` against a temporary synthetic project. Its initial ambiguous request safely fell back in the opted-in arm: both arms read the file and answered correctly, but this was not a successful narrowing or cost-saving measurement. A separate request explicitly identifying a disk path with no database fileId exercised accepted preselection: both arms read the synthetic file and answered correctly in two model rounds; off took 9.710 seconds with 81,773 main input tokens, on took 6.289 seconds with 22,147 main input tokens. Jev added 3,484 input tokens and a $0.000146328 receipt. Main-model cost/cache receipts were not captured in this Java test, so this is token/latency evidence, not a complete dollar-cost measurement. This single pair is not a stable latency estimate or a full Spring/UI product benchmark.

Offline regression covers default-off behavior, invalid consent, durable inbox state, cancellation/late completion, queue/steer isolation, catalog expansion, local routing, total timeout and separate cost attribution. The frontend test renders the real composer and checks visible on/off states, keyboard controls, both languages, narrow widths, persistence and outgoing request snapshots.

All live inputs are synthetic. Credentials stay at their existing location and are passed only in process memory. Live tests are explicitly opt-in and skipped by normal CI. The feature remains experimental: neither speed gains nor production-wide quality equivalence are established by this small sample.

Final local backend regression: 5,014 tests, zero failures/errors, 18 expected skips. This includes the original concurrent-turn contract test: replacing a run revokes its decision advice but must still let that old main run finish its own messages/tools. Frontend build, actual composer browser checks, and SPDX/tool-parity checks passed. CI and merge evidence are tracked in [PR #950](https://github.com/zeweihan/aiworkdeck/pull/950).
