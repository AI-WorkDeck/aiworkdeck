# 桌面消息中心

用户界面的业务层级固定为 **律所 → 团队 → 项目**。消息中心是账号级入口，不再建立“组织”这一层；打开消息中心不必先打开一个项目，也不切换当前案卷。

## 对话、通知与待处理

- 对话：普通私聊/群聊、案件库项目群、律所/团队/项目助手。IM 会话仍保存原消息、附件权限和已读游标，不复制聊天历史到通知表。
- 通知：尽调发布/提交/审核以及插件事件。每条消息保留来源、项目、发生时间和独立已读状态。
- 待处理：业务当前仍等待本人动作的消息。阅读或点开消息只改变已读；确认、放行、退回和终审在原业务内完成，由业务服务更新状态。

云端消息保存在案件库，收件人下一次打开桌面可读取。桌面插件只有运行时才能产生事件。本轮不提供手机推送，也不把站内落库等同于手机/操作系统通知已送达。

## 项目与客户邀请

案件库项目群绑定服务器上的真实项目。进入群聊和每次读写都重新核验项目成员资格；退出项目后，旧会话编号也不能继续访问。会话邀请码只加入普通会话，不授予项目、团队、律所或文件权限。

客户使用项目成员邀请中的**具名客户邀请码**，在“客户协作”连接受邀项目。该连接保存独立客户会话，尽调与项目群都使用同一身份，不改桌面主账号。逐人确认应使用一人一码；通用客户码代表共享客户身份，不能据此声称是哪位个人阅读/确认。客户不会因加入项目群获得团队或律所资料。

本机与案件库的数字项目编号属于不同空间。通知导航按连接和 ProjectRemote 映射；未取回的官方项目需先取回，禁止把远端编号当作碰巧同号的本机案卷。受邀客户连接则直接在该连接内打开清单，不要求取回律师案卷。

项目群直接包含项目助手。已上云项目复用同一个共享群，原有助手群保留为历史讨论，不把旧群材料迁给更多成员。群内回复只使用共同可见内容；私聊保持独立，并在生成前后核对项目权限与角色。客户可查看群内共享回复，助手请求由内部成员发起。

## 律所利冲协作

管理员身份由官网总部团队 OWNER/ADMIN 的当前角色裁决。指派委员后，本人接受当前版本邀请才取得委员资格；申请人从真实账号中选择主办、关联律师和已接受的委员。关联律师只看到发给自己的征询，逐人确认完毕后进入委员终审。非本人不能代答，非委员不能终审，申请人/主办不能自审；退出律所或撤销委员资格后，旧消息入口仍重新鉴权。

这条协作流程以官方案件库的新业务记录为准。旧本机草稿、财务数据和演示流程不自动上传，也不视为跨电脑已通知。申请人明确发起协作时才发送所选摘要。终审通过不等于本机项目已自动创建。本轮没有为存量申请提供终审委员改派入口；撤权后不能代审，需要同一委员重新获指派并接受后继续。

## 插件开发者接口

Web SDK 1.7 新增 `notifications` 权限。插件必须显式声明，升级后仍按既有安装授权流程生效：

```json
{"permissions":["notifications"]}
```

```js
await awd.notifications.publish({
  eventKey: 'review:record-42:v3',
  title: '请确认审查结果',
  body: '审查结果已生成，请核对后确认。',
  actionState: 'pending',
  target: {kind: 'plugin', pluginId: 'my-plugin', view: 'reviews', recordId: 'record-42'}
});
// 完成自己的业务校验并成功保存决定之后，再更新消息状态。
await awd.notifications.resolve('review:record-42:v3', 'done');
```

Web 插件只向当前账号发消息，不能指定收件人或冒充内置业务来源。`eventKey` 在同一插件和收件人内去重，网络重试保留同一键及内容；同键不同内容被拒绝。状态为 `none/pending/done/cancelled`，`resolve` 只接受 `done/cancelled`。标题限 256 字、正文 4000 字、事件键 160 字；每插件每账号每分钟最多 60 条新通知。失败保留业务结果并提示重试，不宣称消息送达。

通知目标仅为数据，禁止 URL、脚本和任意宿主命令。Web 通知只能打开自己的已安装启用插件。宿主复核权限后发送 `sidebar.command` 事件 `{command:'message-open',view,recordId,projectId?}`；插件仍须重新校验记录权限。律所插件复用 `lawfirm.navigate` 的记录定位。

Java 插件使用 SPI 1.4，通过 `PluginHost.notifications()` 使用相同的 `publish/resolve`，无需持有用户凭据。运行在权威案件库服务端的插件还可用 `publishProject(projectId, recipientIds, notification)` 与 `resolveProject(...)`：发送者必须具有当前项目写权限，收件人必须是真实内部项目成员。桌面本机调用跨成员接口被拒绝；CLIENT 收件人通过尽调等明确约束内容的内置业务适配器通知，不向通用插件暴露任意客户投递能力。

宿主内部 `MessageCenterSource` 以只读投影接入现存业务通知；`MessageCenterAccessPolicy` 对无项目的律所事项逐次核验收件权限。HTTP 入口 `/api/message-center/action` 提供 `list/counts/read/target/im/ddClientIm`，插件发布必须经 `/api/plugins/{id}/notifications` 安装、启用和权限检查。接入文档不构成绕过这些检查的授权。

## 验证与交付边界

源代码、宿主安装包、独立插件和云服务分别交付。2026-10-22排查时，本机 project-im 为 0.1.1，而源码为 0.2.0，因此出现新宿主侧栏和旧“我的组织”页面并存。新宿主识别旧 project-im 后显示明确的更新入口，不继续呈现不一致的通讯录。

本轮增加桌面实现和接口契约，未自动发布宿主、上传签名插件、替换云服务或升级用户客户端。使用新接口需配套宿主、案件库和官网目录支持；旧服务不可用时显示来源不可用，不回落到假数据或本机代办身份。
