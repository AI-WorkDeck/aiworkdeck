# 中国法律数据工具包（对齐 Stella legal-atlas / business-registries / sanctions）

> 状态：第一期已实现离线解析部分（本 PR）；外部数据源只做方案，本期不实现任何抓取或出站请求。
> 参考：Stella `packages/legal-atlas`（分法域的条文引用语法、法规身份）、`packages/business-registries`（工商登记的类型化客户端）、`packages/sanctions`。

## 1. 已有能力盘点（避免重复建设）

| 已有 | 位置 | 和本包的关系 |
|---|---|---|
| 中文条号转阿拉伯（第二十条之一 → 20.1），引文剥离 | `service/insight/LawArticleNumbers` | 本包 `LawCitation.articleNumber()` 与它同形，有测试对拍；本期不改它 |
| 法规名 / 条号切分（`splitLawName`），LAW normKey | `service/insight/DocInsightService` | 只切到「第X条」，没有别名归一，也不处理版本括注和列举 |
| 法宝在线工具：`law_recognition`、`anhao_recognition`（案号识别）、`adjust_provisions`（引用校验） | `LegalTools`、`PkulawChannel`、依据窗格 | 在线、付费、需要账户；本包是离线、零成本的前置层，不替代权威核验 |
| 选区右键的本地分类（案号正则、常见法律名单） | `frontend/src/utils/selectionLookup.js` | 只判断「是不是法条/案号」用于摆菜单，不输出结构 |
| 企查查（REST + MCP） | `QichachaService` | 工商登记的已授权数据商通道，见 §4.2 |
| 证据核查四类要素（信用代码、日期、金额、主体名） | `service/evidence/EvidenceChecks` | 接入点见 §3 |
| 官方插件 search / baoqingtian | `official-plugins/` | 分别是项目内全文搜索、包晴天案源账号，和法律数据无交集 |

结论：仓库里有零散的条号转换和案号正则，但没有一个可复用的「引用 → 结构」层。本期补上这一层，不碰现有调用方。

## 2. 本期实现（纯离线）

包：`backend/src/main/java/com/checkba/service/legal/cn/`，无 Spring、无 IO、无网络依赖。

| 类 | 作用 |
|---|---|
| `ChineseNumerals` | 中文/大写/全角/逐位数字 ↔ 阿拉伯数字，0–99,999,999；认不出返回 null，不猜 |
| `LawAliases` | 约 60 部法律的简称/全称/俗称表（民诉法、个保法、破产法……），只做名称归一，不表示现行有效 |
| `LawCitation` | 条文引用解析：书名号或表内法名 + 版本括注 + 条/之X/款/项/目；支持列举（「第577条、第584条」「第一款、第二款」）；`normalized()` 输出规范写法 |
| `CaseNumber` | 2016 年起新式案号解析：年度、法院代字（省份、高/中/基层/最高法）、类型代字（名称、大类）、编号；`normalized()` 统一括号与全角数字 |

**为什么放 Java 后端而不是 TS SDK**：所有消费方都在 Java 里，包括依据窗格管线（`DocInsightService`）、AI 工具（`LegalTools`）、证据核查（`EvidenceChecks`），以及已有的 `LawArticleNumbers`。`sdk/plugin-sdk` 是给插件 Web 面板用的单文件桥接，不是数据包的发布渠道。前端选区分类需要零延迟，所以保留现有 JS。将来如果要像 Stella 那样单独对外发布，这个包不依赖 Spring，可以直接拆成独立 Maven 模块或用 TS 重写，测试用例可以作为共享样本。

**刻意不做的**：「第X条至第Y条」区间、「同法/该法」指代、2016 年以前的旧式案号（「(2015)民二终字第1号」）、行政法规与司法解释的别名（简称不唯一）、法律时效判断。这些情况一律返回 null 或保留原文，不猜。

## 3. 接入 AWD（本期未接入，原因与建议）

本期不改任何现有调用方。下面每个接入点都会改变用户可见行为或现有契约，适合单独开 PR，各自带回归测试：

1. **依据窗格 LAW 去重**：`DocInsightService` 的 LAW normKey 改用 `LawCitation`，让「民法典」与「中华人民共和国民法典」、「民法典577条」与「《民法典》第五百七十七条」合并成一条实体。影响：normKey 变化会让 7 天检索缓存失效一次。条号转换可以改用 `articleNumber()`，同形对拍测试已经写好。
2. **证据核查第五类要素**：`EvidenceChecks.run` 增加案号和法条引用。陈述里的规范化案号如果在底稿中找到，判 supports；找到同法院同年度但编号不同的，判 contradicts；找不到，记「查不到」（`ok=null`），遵守「缺证据 ≠ 矛盾」。需要同步更新 `verify_json` 的 finding 形状和 doc-insight / 证据相关文档。
3. **AI 工具**：可以新增零成本工具 `legal_citation_parse`。但这会涉及 `ToolRegistry`、`toolDisplayNames.js` 的 20 种语言词条、`ToolDisclosurePolicy` 类目，以及 prompt 契约测试，改动不小。建议改为在 `law_recognition` 内部先做离线解析：法宝不可用时，也能返回结构化的条号和规范名。
4. **前端选区分类**：`selectionLookup.js` 中的 `CASE_NUMBER` 正则和 `COMMON_LAWS` 与本包有重复。建议以本包测试用例为准，导出一份共享样本 JSON，前后端各跑一遍，防止两边规则分叉。

## 4. 外部数据源：合法合规接入方式（本期不实现）

总原则：
- 法律、法规、司法文书本身不受著作权保护（《著作权法》第五条）。但网站的**数据库汇编、访问服务和用户协议**受合同法、《反不正当竞争法》以及数据相关法规约束。绕过验证码、登录、频率限制等技术措施批量获取数据，可能构成不正当竞争，情节严重的还涉及《刑法》第二百八十五条。
- **只走官方公开接口、官方批量下载或已授权的商业数据商**；不做绕过反爬的抓取，不伪造 UA 或轮换代理。
- 任何新出站请求都必须先在 `legal/PRIVACY.md` 中声明（CLAUDE.md 硬红线），并说明发送内容、接收方和留存情况。

### 4.1 国家法律法规数据库（flk.npc.gov.cn，全国人大常委会办公厅）

- 现状：网页检索，可以下载 Word/PDF 原文。据我所知，没有公开的开发者 API 和配套的使用条款。网页前端调用的内部 JSON 接口不是对外承诺的契约，**不应直接对接**。
- 合规路径（按优先级）：
  1. **离线快照**：人工或低频（例如每月）从官网下载法律文本，校验后入库。随包分发「法律名称、公布日期、施行日期、时效状态」这类元数据，直接扩展 `LawAliases`。下载频率要克制，并保留来源 URL 和下载时间。
  2. **授权数据商**：北大法宝已经接入（`PkulawChannel`，平台代采或自备 Key）。也可以评估威科先行、元典等，前提是签订覆盖「在产品内向终端用户展示」的授权合同。
  3. 正式向全国人大常委会法工委或数据库运维方申请数据接口或合作（需要用户出面）。
- 风险：内部接口变化或被封禁；如果把下载内容二次分发成数据集，需要先确认汇编部分的权利。

### 4.2 国家企业信用信息公示系统（gsxt.gov.cn，市场监管总局）

- 现状：《企业信息公示暂行条例》规定这些信息「公示」，任何人都可以查询。但网站有滑块/点选验证码和频率限制，属于明确的技术防护措施。**不应抓取**。
- 合规路径：
  1. **继续用企查查**（已接入，`QichachaService`，PRIVACY.md 已声明）。天眼查、启信宝是可替换的同类授权数据商，按 `InsightProperties` 的配置化先例接入，代码里不写死。
  2. 统一社会信用代码的校验位规则（GB 32100-2015）是离线算法，已经在 `EvidenceChecks.usccValid` 中实现，不需要外查。
  3. 部分地方政府数据开放平台提供企业登记数据集，按各平台开放协议使用，需要逐个核对协议。
- 本包对应 Stella `business-registries`：类型化客户端的形状，建议以现有企查查返回结构为基础，抽出一个与供应商无关的 `CompanyRecord`。下一期再做。

### 4.3 中国裁判文书网（wenshu.court.gov.cn，最高人民法院）

- 现状：需要注册登录才能检索；用户协议禁止批量下载和自动化抓取，反爬措施很强。2024 年起，最高法另建了**人民法院案例库**（rmfyalk.court.gov.cn，收录参考案例和指导性案例），面向公众检索。
- 合规路径：
  1. **授权数据商**：北大法宝的案例与案号识别（`anhao_recognition`、`search_case`）已经接入。元典、聚法、威科等可以作为备选，需要合同授权。
  2. 人民法院案例库只供人工检索和引用。AWD 可以根据本包解析出的案号，生成**跳转到官方检索页的链接**，由用户自己打开，不做服务端请求。
  3. 本包的 `CaseNumber` 已经能离线给出年份、省份、法院层级和案件类型。将来可以把最高法《关于人民法院案件案号的若干规定》附件里的**法院代字表**整理成离线数据，把「京01」映射到「北京市第一中级人民法院」。需要确认附件的获取来源和更新机制。
- 风险：裁判文书中包含个人信息，就算通过授权渠道取得，展示和留存也要遵守《个人信息保护法》，并沿用 AWD 已有的脱敏能力（desensitize）。

### 4.4 制裁与管控名单（对应 Stella `sanctions`）

- 国内：商务部「不可靠实体清单」、出口管制管控名单、外交部依据《反外国制裁法》公布的反制清单。这些都以公告形式公开发布，没有机器可读接口。合规做法是人工整理成离线快照，并标注公告文号和日期。
- 境外：OFAC SDN、联合国安理会综合制裁名单、欧盟综合名单都提供官方可下载的 XML/CSV，许可明确，可以定期下载离线快照。下载属于新的出站请求，需要在 PRIVACY.md 中声明，或改为随版本打包。
