# 脱敏插件分析与本地复敏方案

对应开发看板：#552 公司名识别、#553 过度脱敏、#554 复敏。

## 结论

用本地 Java 正则、字段上下文、号码校验和人工词表，能够达到「基本识别、正文可读、可复核」的目标。
公司名和人名无法靠一条正则保证完整、准确，但不必为了这一步把原文交给大模型。
复敏采用「稳定编号 + 单独加密映射」，不从星号或黑框猜原文。

本次实现不引入新依赖、不调用模型或外部识别服务。旧原文和生成结果都由现有本地文件服务读取/登记；
脱敏与复敏控制器没有调用 AI、OCR、embedding 或 RAG。登记文件的 createFile 路径不触发 embedding。
这保证的是本面板处理链路，不是整个工作台的全局外发拦截：用户另行把原文件、项目上下文或复敏后的文件交给 AI，仍可能外发。

## 现状与根因

| 部位 | 原实现 | 问题 | 本次处理 |
| --- | --- | --- | --- |
| 来源 | pom 保留 houbb/sensitive-word 0.2.0，但业务代码没有调用 | 不能靠升级依赖改善本面板的识别质量 | 保留依赖，修实际工作的 Java 识别与替换链路 |
| 公司名 | 没有 COMPANY 策略 | 全称/简称均无法识别 | 增加简繁公司/律所等后缀、常见英文公司名；简称可手工补充 |
| 姓名 | `[一-龥]{2,4}` | 任意中文正文被连续打码 | 字段上下文 + 姓氏判断；角色词要求冒号；识别到的人名在全文重复应用 |
| 密码 | 字母大小写+数字即当密码 | 订单号、代号误判 | 要求密码/口令/password 等字段上下文 |
| 地址 | 长汉字串贪婪匹配 | 容易吞正文，直辖市/字段地址漏检 | 改用明确地址字段和标点边界，仍须人工复核 |
| 数字 | 已有边界、身份证日期/校验位、银行卡 Luhn | 比纯数字好，但有校验位也不等于业务上一定是敏感号码；错号可能漏掉 | 保留原有校验并允许手工补词/保留词 |
| 替换顺序 | 在前一策略改写后的字符串上再匹配 | 不同规则会互相干扰 | 原文统一识别；自定义优先、长匹配优先、重叠只处理一次 |
| 可读性 | 仅星号/黑框 | 无法区分不同主体，也不支持恢复 | 默认推荐编号；相同实体在一个文件内使用相同编号 |
| Word | 只取每个 run 的第一个文本节点；命中后折叠整段 | 漏多文本节点、文本框等，破坏格式 | XML 段落级遍历所有文本节点，跨 run 仅替换命中范围；覆盖嵌套表格/文本框/批注文字/页眉页脚/注释 |
| 文件类型 | 除 DOCX/PDF 外全部当 UTF-8 | 二进制文件可能被损坏 | 格式白名单，非 UTF-8 文本拒绝，限制32MB |
| 界面 | 勾选后直接生成 | 看不到误识别、漏识别、零命中 | 先预览，可补词/排除；显示总数及限制提示；预览最多12000字符，处理覆盖全文 |
| 输出 | 文件名沿用原名 | 原文件名本身可能泄露公司/人名 | 新文件使用中性名称，保留扩展名 |
| 权限 | 有读取权限即可写新文件 | 只读成员也能创建副本 | 预览检查读权限，生成/复敏同时检查写权限 |

当前参考依赖并不是公司/人名实体识别器：
[houbb/sensitive-word 官方仓库](https://github.com/houbb/sensitive-word)主要是敏感词过滤框架。
[Presidio 官方匿名化文档](https://microsoft.github.io/presidio/anonymizer/)同样区分识别与替换，
并说明复原取决于可逆操作。其设计思路可参考，本次不接入它的服务或额外模型。

## 复敏如何工作

例如：

```
原文：甲方：北京星河科技有限公司。联系人：张三。张三代表甲方签字。
结果：甲方：[[公司名称1_ab12cd34ef56]]。联系人：[[中文姓名2_ab12cd34ef56]]。[[中文姓名2_ab12cd34ef56]]代表甲方签字。
```

编号含类别、顺序号、随机会话标识；不包含公司/姓名的原字符。同一原词使用同一编号，不同处理批次使用不同标识。
自动识别先扫描全文建立已知人名/公司名，再分段替换，所以先出现的普通提及也可以由后面的明确姓名字段补足。
自定义词按字面匹配，不把用户输入当正则；保留词按完整识别值排除。不同批次不会自动合并实体。

映射在请求内存中建立，随后使用 PBKDF2-HMAC-SHA256（210000轮、随机16字节盐）派生256位密钥，
AES-256-GCM（随机12字节 nonce）加密，固定版本前缀作为附加认证数据。只把加密后的 `.awd-recovery`
文件返回浏览器下载；不把明文映射写到项目、数据库、日志或模型上下文。
密码由用户自行保存，面板成功处理后清空密码；没有服务器重置密码或找回映射功能。
响应带 `Cache-Control: no-store`。映射最多20000项/加密后8MB，超限要求拆分。

复敏为一次性精确替换，避免还原值中恰好包含另一个编号时被二次替换。密码错误、文件篡改、完全不匹配时不生成副本；
部分编号来自其他映射时，只恢复属于当前映射的编号，其余保持原样并报告。
AI 改写后的文件可以复敏，但 AI 必须原样保留编号。被删、改写、拆散到不同段落的编号不能恢复。
Word 恢复的是文本值，不保证敏感词内部每个原始 run 的格式和原始文件字节完全一致；未命中部分的格式尽量保留。

星号遮蔽和 PDF 黑框不生成映射，不承诺复敏。不能把历史星号「反推」成原始信息。

## 边界与后续可选方向

- 规则是保守启发式，不是精确实体识别。无字段人名、任意公司简称、复杂句子里的公司起始边界、少数姓氏、分行公司名仍可能漏/误识别。
  自动规则之外用补充敏感词；不会偷偷调用大模型补漏。
- 简称目前不自动推断为全称的同一主体。自定义简称能遮蔽，但会分配自己的编号。跨文件统一实体词表属于后续范围。
- DOCX 的图片、签名图、嵌入文件、外链、文档属性、修订作者等不在文字替换保证范围。字段更新也可能把外部内容重新带回。
  批注与修订的文字节点会处理，但不能据此宣称原文件已完全清除所有隐藏信息。
- PDF 仍采用黑框+栅格化移除文字层，正文不可选择；不调用 OCR。
  无文字页（含空白页）、加密、旋转/特殊裁剪页面或不能可靠定位的命中应拒绝，避免伪成功。
  混有图片的文字型页面仍需人工逐页核查。
- UTF-8 txt/md/csv/log 作为文字处理；CSV 的结构语义仍须人工核查。JSON 不在支持范围，避免把裸数字替换成编号后破坏格式。
- 预览基于已保存的文件，编辑后应保存并重新预览。预览编号仅供示意，复敏针对最终生成文件的编号。
- 星号模式保留号码片段、邮箱域名等，可能仍可识别身份。送 AI 推荐完整编号替换。
- 隐藏元数据的彻底清理、图片本地 OCR、本地小型 NER、跨文件共享词典、全局 AI 外发拦截可作为后续独立工程。
  本地 NER 不是云端大模型，但当前版本没有下载或加载任何识别模型。

## 交互对齐（同日第二轮，dev-board#555—#558）

理想的操作是：选择原文件 → 预览并补充/排除识别词 → 生成脱敏副本 → 在编辑区修改 → 本地复敏并打开新的复敏副本。
左侧面板负责选择处理对象与规则，中间文档标签负责查看/编辑，右侧助手保留现有 AI 能力。三个区域的切换不应互相抢占。

| 核查项 | 实际差距 | 本轮落实 |
| --- | --- | --- |
| 点文档标签 | `activateTab` 强制展开侧栏并切回 files | 去掉强制跳转，只同步已经挂载的文件树选中项；当前功能区与折叠状态保持 |
| 脱敏期间看文档 | `isTabVisible` 没有放行 desensitize | 普通文档在各左栏模式下持续可见，特殊插件/尽调标签保留专门规则 |
| 重复打开文件 | 当前窗格会去重，但另一分屏没有去重；字符串/数字 id 也可能重复 | 在两侧查找同一文件并聚焦已有标签，保留已有编辑器身份；不同 id 的同名文件仍独立 |
| 生成后编辑 | 已有 `open-file` 回调，但被上述可见性规则阻碍 | 保持自动打开生成副本；结果区明确说明可以直接编辑 |
| 编辑后复敏 | 需重新选择输出文件并导入刚下载的映射；可能读取未保存的旧内容 | 「复敏这份结果」选择本次输出并复用加密映射，重新输入密码；预览/脱敏/复敏前等待目标编辑器保存，失败即停止 |

面板处理对象不会因点击其他文档标签而悄悄更换；需要换对象时点「导入当前」或「浏览」。
同一次面板使用期间可复用加密映射；关掉面板或跨次使用时，选择脱敏文件，导入单独保存的 `.awd-recovery`，输入密码即可复敏。
自动下载失败会保留映射供重试，仍打开已经生成的副本。PDF 和星号模式没有可逆映射，不出现「复敏这份结果」。
显式拖拽分屏仍允许用户有意把一个文件放在两侧；此处修正的是普通打开动作重复建标签。

生成前如果本次等待保存发现仍有待保存修改，会作废旧预览并要求重新预览。
这不是文件版本锁：预览后已经自动保存的改动、外部程序更改等没有内容哈希绑定，编辑原件后仍应重新预览并核查最终副本。

复敏是面板的本地按钮，不由 AI 执行。手工编辑和 AI 改写都须原样保留完整编号，才能恢复对应内容；复敏生成新文件，不覆盖原件。
普通 AI 助手已有当前文档/显式附件机制，但还可能带入历史消息、项目与记忆上下文，因此本轮**没有实现隔离的「仅使用这份脱敏副本」AI 会话**。
本面板不自动启动 AI，不发送原文、映射或密码给模型；需要使用普通 AI 时仍须核查其材料范围。若产品要保证整个后续 AI 会话只接触脱敏材料，还需单独限制历史、记忆和工具可读文件范围。

本轮验证：工作台相关测试 303 项通过；脱敏面板与保存顺序测试 15 项通过；事件绑定、双语语言键、全量导航契约检查和 H5 构建通过。
另以合成数据和模拟 API 在浏览器挂载实际 Vue/uni 组件，实点按钮及密码输入，跑通预览→生成并打开→复用映射复敏并打开流程；此项不等于完整桌面端到端验证。
本轮只改前端交互，没有重复运行或新增后端测试。尚未打包安装或发布，桌面 Office 编辑器真实保存/复敏仍需安装版复测。
